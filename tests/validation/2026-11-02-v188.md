# 우리 교실 v1.8.8 전국 학교 개발판 검증

2026-11-02에 확인했다. 개발 기준은 main `3a413bb833829055e19a7b22f91a93f1b0d6374b`, 설치파일의 앱 소스는 `6c0b1b8210066199a7545f89c779b1ffabc047b4`다. 이전 버전의 Windows 감사 기록은 그대로 보존했다.

## 학교 선택과 NEIS

- 신규 설치에서 NEIS 도우미, 학교 검색·선택, 학년·반 입력을 확인했다. 같은 이름·학년·반을 가진 가상 학교 두 곳의 교육청·학교코드를 다르게 설정했다. 전환 전 명단·알림장·활동·하이클래스 연결이 두 번째 학교에 나타나지 않았고 원래 학교로 돌아오자 복원됐다.
- NEIS 공개 서비스에서 옥구초등학교 `P10 / 8342104`와 서울교동초등학교 `B10 / 7061058`의 학교정보를 확인했다. 2026-09-21의 실제 급식·초등시간표 응답도 각각의 교육청·학교코드와 대조했다. [NEIS 학교기본정보](https://open.neis.go.kr/hub/schoolInfo) · [초등학교시간표](https://open.neis.go.kr/hub/elsTimetable) · [급식식단정보](https://open.neis.go.kr/hub/mealServiceDietInfo)
- 발급 안내는 공식 포털에서 확인했다. 개인 인증키 발급이나 실제 교사 키로 인증하는 절차는 수행하지 않았다. [인증키 신청](https://open.neis.go.kr/portal/guide/actKeyPage.do) · [공식 개발자 가이드](https://open.neis.go.kr/portal/guide/apiGuidePage.do)
- 하이클래스는 가상의 학급, 수신자, 사진, 세션으로 검사했다. 사진 드라이버가 없을 때 등록이 차단되고 본문·사진이 남았으며 성공 이력과 자동 재전송이 발생하지 않았다. 실제 학생·학부모에게 발송한 건수는 0건이다.

## Windows 설치파일

`npm run dist:win`으로 만든 Windows x64 NSIS 검증 파일은 `dist/classroom-dashboard-setup-1.8.8.exe`다. 크기는 99,316,347바이트, SHA-256은 `12252ef577b626cd68838fc67accc58c4b6572f1dd9e783fddc9c744d8175e7d`다. PE 실행 파일 기종 x64, 앱 버전 1.8.8, 패키지 파일 78개의 소스 일치, 로컬 업데이트 매니페스트의 SHA-512를 확인했다.

검증 환경은 Windows 11 ARM64 빌드 26200의 격리 VM에서 실행한 x64 앱이다. 비교 대상은 공식 v1.8.7 설치파일(SHA-256 `ffbcd03caf69a63f0b77f0dca164f34b05607dfa568a97ccd7ee33dfe1b81741`)이다. 업데이트 검사에 필요한 후보 파일은 루프백 HTTP 서버에서만 제공했다. 물리 x64 PC, 학교 운영 PC, 운영 GitHub에서 v1.8.8을 내려받는 경로는 이 검사 범위 밖이다.

### Windows 기능 회귀

Windows에서 17개 종단간 묶음을 실행했다. 첫 실행에서 문서 폴더를 얻을 수 없는 계정은 백업·복원 창을 열지 못했다. 저장·열기 양쪽에 파일 선택기 기본 위치 처리를 수정하고 영향받는 묶음을 다시 실행했다. 최종 소스의 앱 파일 79개를 Git 해시와 대조하고, 수정의 영향을 받는 5개 묶음과 나머지 12개 묶음을 모두 실행했다. 최종 Windows 검사는 17개 묶음 305/305, 단위 검사 49/49였다. Windows 자동 실행 등록 목록 검사가 포함되어 macOS보다 1개 많다.

### 공식 v1.8.7 앱 내 업데이트

일반 Windows 사용자로 데스크톱에 로그인한 뒤 공식 v1.8.7의 **설정 → 업데이트 → 업데이트 확인 → 업데이트**에서 로컬 피드의 후보를 내려받았다. 실제 설치와 재시작을 거쳐 복구 도우미의 `stage`가 `complete`, 새 앱의 시작 확인 값이 `1.8.8`이 됐다. 같은 사용자 프로필의 합성 명단·활동 기록·알림장 초안을 이전 값과 비교했다. 기존 사진과 이전용 백업의 사진, 하이클래스 연결, 기존 파티션의 로그인 쿠키도 확인했다.

앞선 SYSTEM 서비스 계정 실행에서는 새 설치가 종료 코드 2를 반환하고 복구 도우미가 v1.8.7로 롤백했다. 비대화형 교사 계정의 별도 시도에서는 합성 인증키 연결을 확인하지 못했다. 위 성공 결과는 실제로 로그인한 일반 계정에서 다시 실행한 기록이다.

### Windows 직접 설치

- **기존 설치 폴더**. 일반 교사 계정에서 실행 중인 공식 v1.8.7 앱을 닫고 같은 위치에 검증용 NSIS 설치파일을 실행했다. v1.8.8 실행과 기존 자료·사진·연결·세션 보존 검사가 통과했다.
- **신규 설치**. 격리 계정의 테스트 설치 등록을 보관한 뒤 빈 등록·새 설치 폴더·새 프로필에서 최종 EXE를 설치했다. 첫 화면에 NEIS 도우미가 열렸고 학교 선택 전 학년 입력이 비활성화됐다. 합성 인증 응답으로 연결을 검사해 Windows 암호화 저장과 입력칸 비움, 브라우저 저장소에 평문 키가 없는 것을 확인했다.
- **서로 다른 설치 폴더**. 이전 설치 등록을 남겨 둔 채 다른 빈 폴더로 전환하는 별도 무인 설치 실험에서는 180초 시간 제한에 걸렸다. 기존 등록이 있는 상태로 설치 위치를 변경하는 경로는 검증을 통과하지 못했다.

## 배포와 비용

기존 appId는 `org.school.classroomdashboard`, 사용자 데이터 경로는 `%APPDATA%\classroom-dashboard`, GitHub 채널은 `rlasksk030/class`다. 자동 다운로드 및 종료 시 자동 설치가 꺼진 상태에서 검사했다. 기존 v1.8.7의 학급 데이터·사진·하이클래스 세션은 새 앱이 처음 열기 전에 `migration-v187`에 보관한다. 복구 순서는 [전국학교 시작 안내](../../전국학교_시작안내.md)에 있다.

로컬에서 빌드·검사했다. 작업 전후 저장소 Actions 실행은 15회, 최신 실행은 `37741006999`의 첫 시도였다. 이번 작업의 신규 실행은 0회다. 정식 Release는 `v1.8.7`(ID `424083930`)이다. 기존 설치파일·블록맵·운영 매니페스트가 유지됐다. 전체 품질 게이트 워크플로 설정을 보존했다. 이번 개발판에서 과거 모든 설치 버전 조합의 Actions 매트릭스를 다시 실행하지는 않았다.
