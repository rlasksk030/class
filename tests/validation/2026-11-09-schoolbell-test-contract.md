# 학교종이 구조적 차단 해소와 실제 앱 통합 검증

작업 기준: `40ad1b1819bf201771896e0759b0ae1bef014962`, `feature/schoolbell-diary-nationwide`, Draft PR #5 / Issue #4.

현재 실제 앱 결과: **등록 버튼 → 제목·본문 자동 입력 → 사진 1장·2장 자동 첨부 → 게시 전 다운로드 원본·순서 대조 PASS**. 실제 새 게시·재조회·초안 정리는 아래 최종 실행 결과에서 별도로 판정한다. 기존 브라우저 A/B/C 성공을 이번 앱 PASS로 재사용하지 않았다.

## 고정 차단값의 원인과 새 계약

| 기존 조건 | 기존 원인 | 수정 방식 / 실제 근거 구분 |
|---|---|---|
| `capability.enabled=false` | 정식 활성화와 모든 개발 기술 검증이 같은 gate를 사용 | 생산 gate는 그대로 false. 미패키지 앱 + 명시된 별도 시험 프로필에서만 native 사용자 승인을 받은 1회 transaction gate를 생성. 일반 프로필·패키지·renderer 설정으로 활성화 불가 |
| runtime `permission=()=>null` | 공식 서비스 허용 근거와 구현 공급자가 없음 | 운영 기본 null 유지. 실제 앱 소유 창/학급 ID/앱 학교·학년·반에 묶인 main-process 시험 승인 공급자 추가. `official:false`, `servicePermission:unconfirmed`이며 공식 허용을 생성하지 않음 |
| `identityVerified:false` | 독립 학급 UI에 학교·학년도 및 고유 계정 ID가 없음 | false 유지. 서비스 학급 ID와 실제 학년·반/관리 화면을 읽고, 앱의 학교·학년도 연결은 native 사용자 확인으로 별도 기록 |
| `authorityVerified:false` | 표시명·기본 사진으로 계정과 관리자를 고유하게 동일시할 수 없음 | false 유지. 편집 가능한 관리 화면·관리자 1명은 서비스 UI 근거, 유일 관리자 본인 여부와 본인 알림 허용은 사용자 확인 근거 |
| `classApproved:false`, `testClassApproved:false` | 승인 상태를 공급하는 실제 서비스 증거가 없음 | 두 service flag를 true로 바꾸지 않음. `testContext`가 실제 빈 대상·관리 화면·동일 창·유효한 native 시험 승인을 독립 검증 |
| `actorKey:null` | 사이트의 고유 계정 식별정보 미확인 | null 유지. 표시된 현재 연락처의 일시적 HMAC는 이 프로세스 안에서 계정 표시 변경 탐지에만 사용. 계정 ID/관리자 일치 증거로 쓰지 않고 파일·renderer·GitHub에 남기지 않음 |
| 필수 관리자 수신자 | 학생·부모 0명이어도 관리자에게 알림 가능 | 학생명단 빈 값, 초대 대상 없음, 검색하지 않은 발행 대상의 명시적 ‘구성원 없음’, 필수 관리자 1명을 함께 확인. 본인 관리자 알림은 사용자 승인으로 별도 처리 |

시험 승인은 30분·현재 소유 창·현재 서비스 학급·앱 설정·1회 실행에만 유효하다. 창 종료, 다른 페이지/로그아웃, 계정 표시 변경, 구성원 추가, 만료, 실행 종료 시 차단한다. 저장된 승인 JSON을 복사해도 WeakMap에 등록된 live lease가 아니므로 실행할 수 없다. 교체된 이전 승인도 다시 유효해지지 않는다. 최종 승인은 정확한 제목·본문·초안 날짜·사진 해시와 순서에 묶어 먼저 기록한다.

## 실제 앱에서 발견한 연결 오류

1. 숨겨진 별도 조회 창에서 수신자 dialog가 열리지 않는 경우: 빈 작성 화면을 앱 소유 창에 먼저 준비하고, 개발 시험의 보조 수신자 확인 창은 비활성 표시 상태에서 읽는다. 계정/명단 조회 화면은 숨김 유지. loading 상태를 ‘빈 구성원’으로 인정하지 않는다.
2. 입력 칸으로 초점을 옮기면 발행 방식 메뉴가 닫힘: 실제 UI에서 관찰. 제목/본문에 먼저 초점을 맞추고 native 즉시발행 radio를 다시 읽은 뒤 기존 atomic guard로 입력한다. 예약으로 바뀌거나 radio가 불명확하면 차단한다.
3. 닫힌 미리보기 요소의 DOM 존재 자체를 열린 창으로 판정: 표시 중인 수신자 창/미리보기 iframe을 판정하도록 수정. 실제로 열린 창은 여전히 입력·게시를 차단한다.
4. 수신자 확인창 닫기 완료 전 다음 작업 진행: 비동기 dialog 종료를 기다린다. 수정 후 실제 읽기 확인과 자동 입력·첨부가 통과했다.
5. native 확인창이 학교종이 창 뒤에 남음: 앱 확인창의 부모 창을 앞으로 표시한다. 교사 확인 시간에는 일반 네트워크 작업의 20초 제한을 적용하지 않으며 시험 승인 만료는 계속 적용한다.
6. 최종 승인 뒤 원본 미리보기 닫기 실패: 실제 `commitOnce` 직전 `preview-overlay`로 차단됨. 초안 창에 초점이 남은 상태의 Escape 전송이 원인. 소유 학교종이 창과 부모 문서에 초점을 맞추고, 관찰된 Escape 동작 후 실제 iframe 닫힘을 기다린다. 닫힘이 불확실하면 실패 처리한다. [Electron 공식 동작 조건](https://www.electronjs.org/docs/latest/api/web-contents#contentssendinputeventinputevent).

7. 보내기 클릭 직후 독립 조회가 원래 작성 문서를 바로 새로고침하던 경합: 실제 한 번의 클릭 뒤 조회 실패, 이후 서버 전체 4건/해당 제목 0건 확인. 요청을 중단할 수 있는 이 순서를 수정하여 관찰된 classnews/schoolnews 완료 화면을 기다린 후 새로고침한다. 로컬 시간차 검사에서 서비스 완료 전 새로고침 0회를 확인했다. 실서비스 재검증은 아래에서 별도 판정한다.

날짜·전체 게시물 조회·원본 다운로드·최종 DOM 대조·pending 선저장·중복 방지·성공 이력 저장·변경 없는 초안 초기화는 기존 구현을 재사용했다. 즉시발행에는 없는 날짜 입력란을 추가하지 않았다. 앱 작성일은 초안 날짜, 서버 발행일은 게시 후 표시 날짜로 구분한다.

## 실제 실행 기록

- 앱 자체 로그인 세션과 동일 시험 학급을 재사용했다. 재실행 뒤 로그인과 시험 본문·사진 2장 유지 확인. 외부 브라우저 쿠키/인증정보 복사 없음.
- 실제 학교·학년도는 서비스 증거로 위장하지 않았다. 현재 계정의 관리 화면 편집 가능, 실제 발행 대상 학생 0·부모 0, 필수 관리자 1 확인. 관리자 본인 여부는 기존 사용자 확인과 native 시험 승인으로 구분한다.
- 등록 버튼이 시험 승인 후 활성화되고 기존 publisher를 호출했다.
- 실제 제목·본문 자동 입력, 한글 두 줄 재조회 일치, PNG 2장 자동 업로드, 다운로드 원본 각 97 bytes의 SHA-256·표시 순서 대조 후 native 최종 확인창까지 도달했다. [게시 전 관찰 기록](artifacts/2026-11-09-schoolbell-test-contract/app-prepublish.json).
- 실패한 시도는 보존했다. `input` 단계 실패와 `commitOnce`의 guard 거부는 보내기 이전이다. 각 재준비 전 실제 전체 목록 4건/해당 제목 0건을 확인하고 ‘미게시 확인’을 별도 기록했다. 기존 A/B/C 및 사용자 작성 글은 변경·삭제하지 않았다.
- 사용자가 동일 제목·본문·가상 사진 2장의 1회 게시를 승인했다. 최초 native 최종 확인 뒤에도 `preview-overlay` guard가 보내기 이전에 차단했으며, 실제 전송으로 계산하거나 성공으로 표시하지 않았다. 초안·사진 유지. [차단 진단](artifacts/2026-11-09-schoolbell-test-contract/final-preview-overlay-failure.json).

### 최종 앱 실행 결과 (11월 10일 계속)

최종 사용자 요청에 따라 이전 2장 시험 초안을 시험 데이터 내 별도 보관하고, 제목 `우리 교실 앱 자동등록 최종 시험`, 본문 두 줄, 가상 PNG 1장(97 bytes)으로 준비했다. 앱 재실행 시 작성 날짜가 오늘로 이동하므로 원래 11월 9일 초안을 선택해 보존 상태도 확인했다.

- 실제 앱 자동 입력·1장 업로드·게시 전 원본 해시 대조 후 최종 사용자 승인을 받았다.
- 보내기 동작은 한 번 완료 응답을 받았으나, 20초 내 실제 완료 화면으로 이동하지 않았다. `publication-unverified`로 실패 처리했고 초안·사진과 불확실 이력을 보존했다. 성공/초안 초기화로 처리하지 않았다.
- 독립된 전체 서버 조회: 기존 게시물 4건, 해당 제목 0건. 새 글 등록 확인 실패. [전송 후 진단](artifacts/2026-11-09-schoolbell-test-contract/final-one-photo-unverified.json), [서버 재조회](artifacts/2026-11-09-schoolbell-test-contract/readback-after-final-one-photo.json).
- 이 결과 이후의 재준비는 보내기 이전 대상 검사에서 차단됐다. 전송 횟수에 포함하지 않는다.
- 시험 경로에서는 보내기 응답 뒤 창을 보존하도록 보완했다. 자동 작업과 시험 권한은 종료/회수하되 늦은 요청을 창 종료로 끊거나 실제 오류 화면을 잃지 않는다. 자동 재전송이나 성공 확정 기능이 아니다. 운영 경로는 변경하지 않았다.
- 재시험은 다시 입력·첨부·원본 검증을 완료하고 별도 최종 사용자 승인을 기다리는 중이다. 이 대기 상태를 게시 성공으로 기록하지 않는다.

기존 A/B/C 게시물과 사용자 수동 글은 수정·삭제하지 않았다. 운영 잠금 유지.

## 로컬 검사와 환경 구분

- 최종 전체 Node 회귀 215/215, 구문 134/134. 미리보기 닫힘과 게시 완료 화면 대기 보완 뒤 실행했다. 이후 개인정보 없는 단계 진단만 추가하고 관련 연결 검사를 확인했다.
- native 시험 승인/최종 guard: 대상 변경·예약 변경 차단, 1회 local send/원본 readback/서로 다른 초안·서버 날짜 receipt, 문서 교체 revision 검증. 숨겨진 미리보기·입력 포커스 변경 상황을 포함. **합성 결과이며 실서비스 게시 성공으로 승격하지 않음**.
- 원본 경로 native 검사: 전체 목록·작성 진입·2장 원본·순서/불일치 및 검증 파일 정리 통과. Escape를 보낼 실제 창의 초점과 닫힘 대기를 포함.
- 기존 하이클래스 등록 21/21, 사진 4/4, 학교종이 UI 20/20. 이 작업에서 실행한 검사이며 이전 버전 PASS 재사용이 아님.
- 최초 제한 환경의 Electron launch 실패와 초기 native consent/download 실패 기록을 보존했다. 로컬 실행 권한으로 재검사한 통과 결과와 구분했다.
- Windows는 이전 조사에서 기존 VM의 SYSTEM 실행/실사용자 명령 시간 초과가 확인된 상태. 이번 Windows 제품·설치·업데이트·재부팅·클립보드 검사는 **NOT RUN**. 기존 suspended VM과 증거 보존, 새 VM·서비스·설치 없음.

## 운영·비용·개인정보

브랜치와 PR base의 workflow blob은 `58613481272e59545c0c910d5d6e033a65f0247a`로 동일하며 다른 Windows 브랜치 push와 수동 dispatch만 구독한다. 이 브랜치 push/PR trigger 없음. Actions 기존 총 19회 / 마지막 41977391612. 신규 실행·재실행 요청 없음, 유료 자원 생성 없음. Push 전후 재확인 결과는 최종 기록에 기재한다.

변경은 학교종이 시험 계약·실제 UI 연결·관련 검증 문서에 한정한다. HiClass 코드/배포판/버전/appId/업데이트 채널/기존 감사 자료 유지. main 병합·빌드·Release·정식 배포 없음. PR #5 Draft 유지.

공개 증거에는 합성 원본 해시·크기, 검사 결과와 boolean만 포함한다. 실제 학급 ID, 계정·연락처, 승인 원문 로그, 로그인 세션 및 사진 파일은 포함하지 않는다. 상세 동의 기록은 시험 앱 데이터 안에만 저장한다.

정식 운영 활성화는 별도 검토 사항이다. 공식 허용을 받았다고 기록하지 않으며 production capability=false를 유지한다. 실제 앱 개발 시험 성공 여부와 정식 출시 판정을 분리한다.
