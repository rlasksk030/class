## 실제 서비스 결과

사용자가 직접 로그인한 연결 브라우저에서 사용자 본인의 새 시험 학급만 사용했다. 비밀번호·인증코드·쿠키를 받거나 추출하지 않았고 비공개 API를 호출하지 않았다. 합성 문구와 가상 PNG만 사용했다.

## 학급·수신대상·허용 범위

- 학생명단에는 30개 빈 입력 슬롯이 있었고 이름/보호자 연락처 1/보호자 연락처 2/학생 연락처의 채워진 값은 각각 0건이었다. 빈 슬롯을 가입 학생 수로 세지 않았다. 초대 화면은 대상 없음으로 표시했다. 명단 값은 수집하지 않았다.
- 관리자 표시는 1명이며 발행 대상 관리자 체크는 해제할 수 없었다. 사용자에게 유일 관리자가 본인인지, 본인 알림을 허용하는지 확인한 뒤 A/B/C를 각각 승인받았다. 학생·학부모 모두 없다는 사용자 재확인도 받았다.
- 이 관찰과 사용자 확인은 **제품의 자동 교사 권한/학급 승인/학교·학년도 매핑 PASS가 아니다**. 실제 UI에서 안정적으로 검증하는 코드가 더 필요하다.
- 과거의 공식 허용 전 모든 실서비스 조작 차단 지침은 사용자의 최신 시험 지시와 가상 사진 업로드 승인으로 시험 범위에서 대체됐다. 초기 사진 업로드 자동 승인 심사 거절 후 범위를 명시해 확인받았다. 최종 게시마다 별도 승인했다.
- 이용약관 화면의 관련 조항을 읽었으나 외부 UI 자동화에 관한 명시적 허용 답변은 확보하지 못했다. 확인한 범위를 서비스 전체의 공식 승인으로 해석하지 않는다. 문의 발송/유료 서비스 신청 없음. 운영용 공식 근거·최종 활성화 승인은 여전히 별도 조건이다.

## 구현

- `schoolbell.cjs`에 기존 publisher/prepared driver를 사용하는 지연 생성 Electron 드라이버를 연결했다. main 코드의 권한·증거 공급자가 없으면 창을 열기 전 차단한다. capability.enabled=false 유지, 환경변수/설정/IPC 활성화 경로 없음.
- `schoolbell-observed-composer.cjs`: 공식 HTTPS, 격리 world, 유일 요소, 동기 DOM 대상 재검사, 변경 revision, 한글 조합 중 차단, 작업 중첩 거부. 제목 native setter/input/change, 본문 native 편집 명령과 정확한 재조회. HTML 주입 없음.
- `schoolbell-editor-text.cjs`: 실제 Froala 문단의 의미상 줄바꿈을 읽는다. 사용자 공백을 trim하지 않고 알 수 없는 비텍스트 요소는 차단한다. 실제 작성 DOM/미리보기와 대조했다.
- 관리 사진 원본을 검증한 후 File/DataTransfer와 관찰된 file input 이벤트로 순서대로 연결한다. localStorage나 외부 호스팅을 추가하지 않는다. 파일 선택은 업로드 성공으로 간주하지 않는다.
- `probeAttachments`: 실제 파일명/확장자 span을 별도로 읽어 `(1.92 KB)`와 같은 용량 라벨을 제외한다. 업로드 UI 종료·순서를 검사하고 독립 원본 검증 공급자를 추가로 요구한다.
- `schoolbell-observed-post.cjs`: 관찰된 classnews 경로와 게시물의 제목·본문·파일 목록을 읽고, 첨부 목록 펼치기/파일 클릭 → Electron will-download → 원본 형식·크기·SHA-256·순서 대조를 구현했다. 앱 데이터 내 전용 임시 검증 폴더만 정리한다. 사용자 사진/초안/이력은 삭제하지 않는다. 게시물 ID·날짜·권한을 추측하지 않는다.
- `schoolbell-electron-driver.cjs`: 위 입력/첨부/읽기 코드를 기존 처리기에 연결한다. 게시 후 검증된 메타데이터를 공급받으면 실제 관찰 UI 다운로드 경로를 사용한다. 공급자가 없으면 실패한다.
- 최종 보내기 1회 응답 후의 공식 사이트 내부 이동은 허용하되, 원래 학급으로 읽기 전용 재조회한 뒤 전체 binding을 재검증한다. 이동한 화면을 게시 성공으로 보지 않는다.
- pending 선저장, 사진 내용·순서 기반 중복 방지, 결과 불확실 시 재전송 금지, 성공 증거 저장 후 변경되지 않은 초안만 전환하는 기존 로직을 유지했다.

**이번 실서비스 실행은 연결 브라우저의 UI 자동화다. 위 Electron 모듈을 실제 로그인 세션에 넣어 실행한 것은 아니다.** 프로덕션 파일 입력 이벤트/Froala 입력/원본 다운로드 경로 자체는 로컬 Electron에서 실행했고, 실서비스에서는 대응 UI 동작과 결과를 검증했다.

## 남은 정확한 조건

| 범위 | 상태와 필요한 작업 |
|---|---|
| 앱의 실제 로그인 세션 | NOT RUN — 브라우저 세션을 추출/이식하지 않음. 앱 창에서 사용자 직접 로그인 후 검증 필요 |
| 학교/학년도/학년/반·교사 권한·수신대상 자동 대조 | BLOCKED — 실제 UI 근거를 한 화면/계정 binding으로 검증하는 provider/원자적 guard 미완성. 사용자 입력만으로 통과하지 않음 |
| 날짜 | BLOCKED — 앱 작성 날짜와 사이트 게시 시각의 의미·일치 규칙 미확정. 임의 날짜 선택자 없음 |

| 원격 중복 baseline/게시물 ID·날짜 metadata 자동 수집 | BLOCKED — UI 링크 복사로 실제 식별정보는 확인했으나, 목록 완결성/독립 메타데이터 provider는 미구현. 임시저장/예약/게시 상태를 혼동하지 않음 |

| 공식 운영 허용/최종 활성화 | 미확인 — 사용자 시험 승인과 서비스 공식 허용을 구분. 운영 capability 잠금 유지 |
