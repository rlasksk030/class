현재 학교종이 작성창은 유지했다. 해당 창에 보존할 미완료 내용/첨부가 없는지 사용자에게 확인을 요청했다. 답변 전에는 닫거나 입력 내용을 덮어쓰지 않는다. 불일치 원인은 학급 이름 파서가 아니라 저장된 앱 설정이므로 파서를 완화하거나 `gradeClass=true`로 바꾸지 않았다.

## 변경 범위

- `schoolbell-recipients.cjs`, `schoolbell-live-context.cjs`, `schoolbell.cjs`: 현재 화면의 역할별 선택/변경 가능 상태를 제한된 boolean과 표시 행 수로 전달한다. 이름·연락처·수신대상 원문은 IPC/진단으로 전달하지 않는다. 전체 학생/보호자 수는 null, `recipientsVerified`는 false다.
- `schoolbell-nonpublishing.cjs`: 개발 시험 프로필에서 고정된 가상 제목·본문·PNG 한 장만 준비하는 별도 경로. 현재 문서/학급과 수신대상, 처음부터 빈 작성 화면, 교사 협조 확인을 요구한다. 기존 제목·본문·첨부, 학급/수신자 변경, 원본 불일치 및 예약 상태를 차단한다. 게시/예약/임시저장·이력 성공·앱 초안 초기화 경로가 없다.
- 기존 `schoolbell-observed-composer.cjs`의 제목/본문/파일 입력을 재사용한다. 새 가드가 동일한 본문 판독기를 사용하도록 읽기 전용 인자 하나만 추가했다. 보내기·커밋 비교 및 기존 게시 승인 규칙은 바꾸지 않았다.
- 앱 개발 검사 영역에 ‘일반 학급 비게시 입력·사진 검사’를 연결했다. main에서 현재 학급과 정확한 합성 자료를 표시해 확인한 경우만 진행하며, 기존 테스트 게시 승인은 폐기하고 재사용하지 않는다. 패키징된 운영 앱에서는 사용할 수 없다.
- 실제 서비스의 고유 계정/학교/학년도 검증과 사용자 확인을 구분한다. 비게시 검사 성공은 게시 권한, 공식 서비스 허용 또는 운영 활성화 증거가 아니다.

## 다음 재개 지점

1. 기존 작성창에 보존할 내용이 없음을 확인하거나 별도 보존한 후에만 창을 정리한다.
2. 앱의 1학년 2반 설정을 실제 저장하고 같은 일반 학급을 새로 연결한다. 필요한 경우 교사가 앱 안에서 직접 로그인한다. 쿠키나 기존 테스트 학급 승인을 복사하지 않는다.
3. 수정 앱에서 실제 학급/수신대상 재확인 후 승인된 합성 자료만 비게시 입력·첨부·원본 대조한다. 보내기/예약/임시저장은 계속 0회로 유지한다.
