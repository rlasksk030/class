# 학교종이 진단 작성창 정리 및 수정 앱 재실행

검증 코드: `386f5b517d23d9121987018068f1ac934953def9`. 사용자가 진단 작성창 취소와 정상 재실행을 승인하되 취소 전 모든 내용 보존, 기존 게시 재조회, 자동 재전송 금지를 요구했다. 게시 범위를 확대하지 않았으며 이번 검증에서는 보내기를 실행하지 않았다.

## 보존과 정상 재시작 — PASS

- 실제 진단 작성 화면의 제목·두 줄 본문은 기존 합성 보존본과 완전히 일치했다. 첨부파일은 0장이었다.
- 앱 본창은 이전 종료 시도에서 이미 닫혀 있었다. 앱 저장 데이터만 복사본으로 읽어 기존 백업/복원 코드로 제목·본문·사진을 확인했다. 외부 브라우저/학교종이 쿠키·인증정보는 읽거나 복사하지 않았다.
- 앱 초안은 기존 시험 날짜에 1건, 제목·본문 일치, PNG 1장 97 bytes였다. 원본 SHA-256은 `1d6f13d252fe9b29809f8d04f04872a5013025bf0e5fb34e57c16bc50381ccc3`와 일치했다.
- 로컬 보존 백업의 체크섬 파싱 및 별도 복원 폴더의 사진 복원 검사를 통과했다. 이 백업은 `.out` 안에만 보관하며 GitHub에 올리지 않는다.
- 내용 대조 뒤 진단 작성창을 취소했다. 기존 앱 프로세스의 정상 종료를 확인한 뒤 같은 시험 프로필로 수정 앱을 실행했다. 강제 종료하지 않았다.
- 재실행한 앱에서 제목·본문·사진 1장 표시와 앱 자체 학교종이 로그인 세션 유지를 확인했다.

## 서버 재조회 및 중복 방지 — PASS (게시 성공 아님)

작성창 정리 직후 새로고침한 목록에 기존 합성 A/B/C와 기존 수동 게시물만 있었다. 앱의 독립 전체 목록 조회도 4건/동일 최종 시험 제목 0건으로 완료됐다. 이전의 미확인 시도 때문에 앱 등록 준비가 차단되는 것을 확인했다. 실제 전체 재조회 근거로 기존 시도를 미게시 확인 처리하되 실패 기록을 보존했다. 게시 성공으로 변경하거나 자동 재전송하지 않았다.

## 수정 앱 비게시 준비 검증 — BLOCKED

현재 테스트 학급·학생 0명·학부모 0명·필수 관리자 1명을 다시 대조했다. 학교·학년도 및 관리자 본인 여부는 기존 사용자 확인과 구분해 기록했다.

같은 제목·본문·기존 PNG 1장 초안으로 입력 준비를 진행했다. 실제 제목과 본문 자동 입력은 완료됐으나 본문 입력 직후의 대상 재검증에서 `context-unverified`로 중단됐다. 기록상 `attachFiles`, `commitOnce`, `native-send` 단계는 호출되지 않았다. 앱 결과는 보수적으로 uncertain으로 남았다. 더 세부적인 내부 원인은 이번 진단만으로 확정하지 않는다.

따라서 사진 원본이 앱에 복원된 것은 PASS지만 이번 경로의 새 자동 업로드와 새 보내기 대기 수정의 실서비스 동작은 NOT RUN이다. 기존 입력/첨부 성공 기록으로 이번 미실행 부분을 PASS 처리하지 않는다. 같은 준비 또는 보내기를 반복하지 않았다.

중단된 웹 작성창은 보존본과 동일한 제목·본문, 첨부 0장임을 다시 대조한 뒤 승인된 범위에서 정리했다. 마지막 독립 전체 재조회(2026-11-10 03:30 UTC)도 4건/동일 제목 0건이었다. 앱 본창의 초안·사진을 재확인하고 실행 상태로 남겼다. 새 성공 이력이나 초안 초기화는 없다.
