# 학교종이 실제 앱 UI 및 직접 로그인 수정 — 2026-11-09

기준 `f1c5bd155c5fbdeb9ac161eb3a7c4f828b3ffdf4`, 코드 `a8d1edb3e5e1a0b5a94596a60f37ec0e4ec2fe34`, 기존 `feature/schoolbell-diary-nationwide` / Draft PR #5 / Issue #4. **앱 버튼·직접 로그인 화면 진입은 실제 확인. 자동 등록 완주는 아직 BLOCKED, 출시 NO GO.** 기존 A/B/C 게시 및 원본 대조 증거는 보존하고 재실행하지 않았다.

## 실제 앱에서 확인하고 고친 문제

- 현재 개발 소스를 Mac Electron 40.10.6으로 별도 시험 프로필에서 실행했다. NEIS 키 없이 공개 학교 검색이 동작했고, 학교·6학년·1반 설정이 저장된 대시보드와 알림장에 도달했다. 이 시험용 설정을 실서비스 학교·권한 증거로 취급하지 않는다. 기존 사용자 데이터는 사용하지 않았다.
- 알림장 서비스 선택에 학교종이가 표시되고 재실행 후 유지됐다. 학교종이 등록 버튼은 하단에 표시되며 운영 잠금에 따라 비활성이다. 이전 기록의 ‘설정 화면이라 버튼 미확인’ 상태를 이번 실제 UI 확인으로 갱신한다.
- 연결 창이 비어 있던 원인은 첫 주소 `https://schoolbell-e.com/`가 `http://schoolbell-e.com/en/main`으로 302 응답하고 기존 HTTPS 검사에 차단되는 것이었다. 인증정보 없는 공개 HEAD 응답으로 대조했고, 이미 관찰한 `https://schoolbell-e.com/ko/main`(200)으로 진입을 바꿨다. HTTP·외부 주소 허용 범위를 넓히지 않았다.
- 앱 버튼으로 실제 v4 학교종이 로그인 화면이 열렸다. 사용자에게 비밀번호를 받거나 다른 브라우저 세션을 복사하지 않았다.
- 사용자가 보고한 ‘웨일스페이스 로그인 버튼 무반응’을 실제 앱에서 재현했다. 학교종이의 `/oauth2/v1.1/authorize` 요청, v4 `/ko/gate/login` 공개 복귀 경로의 `return_uri`·`provider` 항목, `auth.whalespace.io → authn.whalespace.io → auth.worksmobile.com` 인증 이동을 앱 안에서 확인했다. 전체 인증 URL/코드/상태/계정 값은 출력·저장하지 않았다.
- 해당 로그인 화면에서 시작한 인증에만 정확한 호스트 목록을 허용하고 원래 공개 복귀 항목과 경로를 고정했다. 학교종이 외부 임의 복귀 주소, HTTP, 사용자명/비밀번호 포함 URL, 다른 게시물에서 시작한 인증, 복귀 항목 변경을 차단한다. 게시판 저장용 `safeURL` 규칙은 그대로다. API 호출·토큰 교환·쿠키 읽기/복사를 구현하지 않았다.
- 수정한 앱에서 **실제 웨일/네이버웍스 Login 화면의 ID 입력란 및 로그인 버튼 표시**를 확인하고 사용자에게 직접 로그인을 인계했다. 이후 사용자가 로그인 완료를 알렸으며 **같은 앱 소유 창에서 로그인된 테스트 학급 알림장과 작성하기 버튼**을 확인했다. 인증정보를 받거나 외부 브라우저의 로그인 세션을 옮기지 않았다.
- 이어 실제 앱의 **연결 상태 확인** 버튼을 실행했다. 결과는 `학년·반 일치`, `발행 대상 구성원 없음`이었다. 사용자는 구성원 0명이 테스트 학급의 정상 상태임을 다시 확인했다. 구성원 없음은 차단 사유가 아니라 통과한 시험 조건이다. 학교/학년도 독립 근거, 현재 계정 고유 식별 및 교사·관리자 일치, 필수 관리자 알림은 미검증으로 반환됐다.
- 로그인 후 SPA 학급 이동에서 창 상태가 계속 로딩으로 표시되는 문제도 발견했다. 같은 문서 내 이동은 일반 페이지 로딩으로 남겨 두지 않도록 고쳤고 해당 변경을 단위 검사했다. 로그인된 창을 보존했으므로 이 마지막 상태 표시 수정의 실제 앱 재시작 확인은 NOT RUN이다.
- 기존 `loadURL`의 초기 ERR_ABORTED가 정상 스크립트 리디렉션에도 생길 수 있어, 허용된 후속 화면 로드를 구분했다. 실제 연결 시간 초과도 한 차례 발생했고, 새 오류 안내 후 명시적 연결 재시도로 회복했다. 인증서/접근 제한을 우회하지 않았다.

## UI·호출 경로

`diary-schoolbell.js`의 학교종이 연결하기 버튼을 접힌 메뉴 밖으로 꺼냈다. 기대 학급·연결 상태·운영 잠금 사유를 바로 보여 주고, 수동 도우미는 별도 접힌 영역에 보존했다. 긴 수동 확인 폼이 기본 본문 영역을 차지하지 않도록 정리하고 서비스 라벨의 줄바꿈을 고쳤다. 앱으로 돌아올 때 창 상태를 갱신한다.

실제 호출은 연결 버튼 → preload `schoolbell:open` → main IPC → 학교/학급별 전용 partition의 BrowserWindow → 공식 HTTPS 화면이다. 새 `schoolbell-window.cjs`는 창 없음/로딩/로그인/학급 화면/연결 실패/차단/시간 초과를 안전한 메시지로 구분한다. 창 상태는 인증·학교·교사 권한 증거가 아니다. 진단에는 차단된 호스트만 포함하며 경로·query·계정·쿠키는 저장하지 않는다.

등록 버튼 → 기존 공통 초안 스냅샷 → IPC publisher → 기존 Electron driver/guard → 영수증 저장 → 변경 없는 초안 정리 경로는 유지했다. **운영 capability는 계속 false이며 이번에 실제 등록 호출을 강제하지 않았다.** 수동 도우미를 자동 등록 완료로 표시하지 않는다.

## 단계별 판정

| 실제 앱 단계 | 이번 결과 |
|---|---|
| 학교 설정 → 알림장 → 서비스 선택 | PASS: 실제 개발 앱 표시 및 선택 저장 확인 |
| 학교종이 연결 버튼 → 앱 전용 로그인 화면 | PASS: 실제 서비스 로그인 양식 표시 |
| 웨일스페이스 버튼 → 실제 ID 입력 화면 | PASS: 기존 무반응 수정 및 실제 화면 확인 |
| 사용자 직접 로그인 → 앱 소유 학급 알림장 | PASS: 사용자 로그인 후 실제 앱 창에서 확인 |
| 앱 연결 검사 → 학년·반 / 구성원 없음 | PASS: 실제 provider 결과 확인 |
| 학교·학년도 / 현재 교사·관리자 / 필수 알림 검증 | BLOCKED: 기존 live provider에 충분한 근거 없음 |
| 학교종이 등록 버튼 표시/운영 차단 | PASS: 표시 및 비활성 상태 확인 |
| 앱 제목·본문·사진 자동 입력 | NOT RUN / BLOCKED |
| 최종 승인 → 실제 게시 | NOT RUN / BLOCKED, 신규 게시 0회 |
| 새 게시물 서버 재조회 → 초안 초기화 | NOT RUN / BLOCKED |

로그인 이후에도 기존 live provider의 학교·학년도·고유 현재 교사와 관리자 일치, 필수 관리자 본인 알림, 게시 전 날짜 의미, 원본 다운로드/전체 목록 조회의 실제 앱 검증이 필요하다. 이 코드의 미검증 값과 운영 허용·활성화 승인을 로그인 하나로 해결됐다고 표시하지 않는다. 실제 새 게시마다 별도 최종 확인이 필요하다.

## 변경 검증 및 보존

- 구문 검사 `npm run check`: 125/125 파일 파싱 통과. `git diff --check` 통과.
- 연결/인증 변경 검사 및 직접 영향받는 기존 서비스 저장 검사: 15/15 통과. 이후 실제 SPA 상태 문제 수정에 해당하는 창 검사만 3/3 추가 실행했다(기존 2 + 새 1). 초기 연결 검사 4개 이후 실제 인증 경로가 바뀌어 최종 검사에 반영했다. 이전 게시 합성 suite를 반복하거나 그 PASS를 실제 앱 결과로 쓰지 않았다.
- 기존 수동 도우미 E2E는 접힌 영역 열기와 구체적 연결 오류 문구에 맞춰 유지했다. 이 문서 작성 시 해당 E2E와 하이클래스 전체 회귀는 NOT RUN이다.
- 하이클래스 driver/publisher, 공통 초안/사진/백업·복원, 버전/appId/전국용·옥구초용 배포 및 업데이트 채널 변경 없음. Windows 최종 제품·설치·업데이트·재부팅·클립보드 검사는 NOT RUN이며 이전 VM guest 환경 차단과 분리한다. 이번 새 VM·빌드·설치 없음.
- 시험 프로필·원본 런타임 로그는 `.out/`에 격리하고 Git 제외했다. GitHub에는 고정 진단과 익명 합성 검사 결과만 넣는다. 기존 감사·실패 기록을 삭제하지 않았다.
- 외부 브라우저에서 공개 로그인 경로를 조사하려던 1회 요청은 자동 승인 심사가 기존 세션 접근 우려로 거부했다. 이후 외부 브라우저를 이용하지 않고, 앱 소유 창에서 공개 호스트·경로만 확인했다. 로그인 화면 진입은 이 안전한 방식으로 해결했다.

인증 경로의 공식 자료는 [Whalespace Login API](https://developers.whalespace.io/guide/login-api), [Whalespace 연결 도메인](https://developers.whalespace.io/guide/caution), [NAVER WORKS 인증](https://developers.worksmobile.com/kr/docs/auth-oauth)이다. 이 자료를 학교종이 자동 발행 허용 근거로 취급하지 않는다.
