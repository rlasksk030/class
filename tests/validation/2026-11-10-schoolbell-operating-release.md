# 학교종이 일반 운영 연결 및 Windows 배포 게이트

기준: `e90311f` / `feature/schoolbell-diary-nationwide` / PR #5 (대상은 `feature/timer-pip-nationwide`, main 아님).

## 구현과 근거의 구분

- 새 `schoolbell-operating-authorization.cjs`는 main process에만 존재하는 30분짜리 학급 연결을 관리한다. 서비스 학급 ID, 현재 앱 세션, 관리 화면 접근, 계정·관리자 화면의 일시적 관찰값, 역할별 수신 선택에 연결한다. 원문 연락처·명단·관찰 해시는 승인 파일이나 IPC로 내보내지 않는다.
- 학교·학년도·로그인 본인 여부는 교사의 기본 확인창 승인 근거다. 서비스 고유 신원 검증으로 바꾸지 않으며 `actorKey=null`, `identityVerified=false`, `authorityVerified=false`, `official=false`, `servicePermission=unconfirmed`를 유지한다.
- 관리자 필수 선택과 보호자1·보호자2·학생의 실제 선택 상태를 매번 대조한다. 표의 표시 행 수는 전체 가입·발송 인원이 아니다. 학급·관리자·로그인 관찰값·대상·필터가 바뀌면 연결을 폐기한다.
- 기존 앱 등록 버튼→드라이버→최종 확인→단일 게시→서버 원본 재조회→이력→변경 없는 초안 전환 경로에 운영 계약을 연결했다. 최종 승인은 정확한 제목·본문·사진 해시에 한정되며 시도 종료 후 소모된다. 연결 자체는 유지되지만 다음 게시에는 새 최종 확인이 필요하다.
- 결과 불확실 시 조회 전용 재검증은 운영 계약의 승인 이력도 검증한다. 재전송하지 않는다. 이번 검사로 발견한 저장소의 개발 시험 전용 제한을 수정했다.
- 포커스를 얻으며 즉시발행 메뉴가 닫힌 경우 읽기 전용 날짜 재확인을 수행한 후 전체 최종 내용을 다시 검증한다. 예약/미확인 날짜를 통과시키지 않는다. 게시 후 수신 확인용 창은 정식 연결에서도 필요한 경우 비활성 표시하여 숨긴 창의 모달 누락을 피한다.
- 운영 `capability.enabled=false` 유지. 기존 실제 테스트 게시 및 일반 학급 비게시 성공을 이번 새 운영 계약의 실환경 PASS로 재사용하지 않는다. 실제 학생·학부모 대상 발송/예약/임시저장 0회.

## Windows와 설치 파일 분리

- 기존 VM만 재개했다. 사용자가 직접 PIN 로그인했고 바탕화면 진입을 확인했다. Parallels UI의 `Tools 설치 중` 상태에서 게스트 명령은 timeout / Invalid argument로 실패했다. 제품 테스트 실패와 구분한다.
- 기존 VM은 ARM64 Windows이며 x64 프로그램 실행은 에뮬레이션 검사다. Windows x64 네이티브 환경 검증으로 기록하지 않는다.
- Node 22.14.0 x64 공식 `SHASUMS256.txt`와 실제 다운로드 ZIP의 SHA-256을 독립 대조했다: `55b639295920b219bb2acbcfa00f90393a2789095b7323f79475c9f34795f217`. 스크립트 고정값과 일치한다. 사용자/시스템 PATH를 변경하지 않고 현재 검사 프로세스에만 portable Node를 추가하도록 보완했다.
- 별도 검증판은 appId·제품명·설치 위치·사용자 데이터 폴더를 정식판과 분리한다. 자동 업데이트와 Windows 자동 실행 등록/정리를 차단한다. 정식 데이터 폴더 지정 환경변수도 검증판에서는 무시한다. 정식 채널과 옥구초에는 영향을 주지 않는다.
- 검증 EXE는 정식 업데이트가 아니며, v1.8.11에서의 실제 업데이트 검사를 대체하지 않는다.
