# 학교종이 일반 운영 연결 및 Windows 배포 게이트

기준: `e90311f` / `feature/schoolbell-diary-nationwide` / PR #5 (대상은 `feature/timer-pip-nationwide`, main 아님).

## 구현과 근거의 구분

- 새 `schoolbell-operating-authorization.cjs`는 main process에만 존재하는 30분짜리 학급 연결을 관리한다. 서비스 학급 ID, 현재 앱 세션, 관리 화면 접근, 계정·관리자 화면의 일시적 관찰값, 역할별 수신 선택에 연결한다. 원문 연락처·명단·관찰 해시는 승인 파일이나 IPC로 내보내지 않는다.
- 학교·학년도·로그인 본인 여부는 교사의 기본 확인창 승인 근거다. 서비스 고유 신원 검증으로 바꾸지 않으며 `actorKey=null`, `identityVerified=false`, `authorityVerified=false`, `official=false`, `servicePermission=unconfirmed`를 유지한다.
- 관리자 필수 선택과 보호자1·보호자2·학생의 실제 선택 상태를 매번 대조한다. 표의 표시 행 수는 전체 가입·발송 인원이 아니다. 학급·관리자·로그인 관찰값·대상·필터가 바뀌면 연결을 폐기한다.
- 기존 앱 등록 버튼→드라이버→최종 확인→단일 게시→서버 원본 재조회→이력→변경 없는 초안 전환 경로에 운영 계약을 연결했다. 최종 승인은 정확한 제목·본문·사진 해시에 한정되며 시도 종료 후 소모된다. 연결 자체는 유지되지만 다음 게시에는 새 최종 확인이 필요하다.
- 결과 불확실 시 조회 전용 재검증은 운영 계약의 승인 이력도 검증한다. 재전송하지 않는다. 이번 검사로 발견한 저장소의 개발 시험 전용 제한을 수정했다.
- 포커스를 얻으며 즉시발행 메뉴가 닫힌 경우 읽기 전용 날짜 재확인을 수행한 후 전체 최종 내용을 다시 검증한다. 예약/미확인 날짜를 통과시키지 않는다. 게시 후 수신 확인용 창은 정식 연결에서도 필요한 경우 비활성 표시하여 숨긴 창의 모달 누락을 피한다.
- 운영 `capability.enabled=false` 유지. 기존 실제 테스트 게시 및 일반 학급 비게시 성공을 이번 새 운영 계약의 실환경 PASS로 재사용하지 않는다. 실제 학생·학부모 대상 발송/예약/임시저장 0회.

## Windows와 설치 파일 분리

- 기존 VM만 재개했다. 사용자가 직접 PIN 로그인했고 바탕화면 진입을 확인했다. Parallels UI의 `Tools 설치 중` 상태에서 게스트 명령은 timeout / Invalid argument로 실패했다. 제품 테스트 실패와 구분한다.
- 기존 VM은 ARM64 Windows이며 x64 프로그램 실행은 에뮬레이션 검사다. Windows x64 네이티브 환경 검증으로 기록하지 않는다.
- Node 22.14.0 x64 공식 `SHASUMS256.txt`와 실제 다운로드 ZIP의 SHA-256을 독립 대조했다: `55b639295920b219bb2acbcfa00f90393a2789095b7323f79475c9f34795f217`. 스크립트 고정값과 일치한다. 사용자/시스템 PATH를 변경하지 않고 현재 검사 프로세스에만 portable Node를 추가하도록 보완했다.
- 별도 검증판은 appId·제품명·설치 위치·사용자 데이터 폴더를 정식판과 분리한다. 자동 업데이트와 Windows 자동 실행 등록/정리를 차단한다. 정식 데이터 폴더 지정 환경변수도 검증판에서는 무시한다. 정식 채널과 옥구초에는 영향을 주지 않는다.
- 검증 EXE는 정식 업데이트가 아니며, v1.8.11에서의 실제 업데이트 검사를 대체하지 않는다.

## 후속 검사 결과와 재사용 범위

- Mac E2E는 초기 중단 이후만 이어 모든 필수 스크립트를 완료했다. 운영 연결 필수 조건을 합성 IPC에도 반영했고, 누락된 최종 발행 동작의 새 오류 코드(`commit-action-mismatch`)를 기대하도록 오래된 검사를 정정했다. 차단·초안 보존·단일 전송 조건은 그대로 검사했다.
- 검증 EXE `1.8.11-validation.55b32b976a4d`, 99,402,885 bytes, SHA-256 `b827abb608bb7bae8de812b1dc87781b3510604dc7c35c57ad14895d263e6f52`. 패키지 내부 132개 소스가 커밋 `55b32b976a4d2c1e37ff11489d9a43f21671e9f7`과 일치한다. 정식 Release/feed에는 올리지 않았다.
- 새 운영 계약의 실제 앱 연결 확인을 위해 기존 작성창을 확인했다. 제목·본문은 이전 승인된 합성 비게시 문구와 일치하고 첨부 이름은 기존 원본 해시와 일치했다. 앱 쪽 초안의 보존 확인 도중 화면 제어가 시간 초과되어 창을 닫거나 재실행하지 않았다. 새 계약 실환경 검증은 BLOCKED이며 이전 비게시 PASS와 구분한다.
- 사용자의 후속 지시에 따라 변경 없는 NSIS 설치 절차 A–I는 2026-11-05 v1.8.11의 기존 증거를 재사용한다. `build/installer.nsh`, `build/prepare-nsis.cjs`, 업데이트 복구 실행 파일, 백업·복원 원본은 PR 기준과 변경 없음이다. 기존 증거를 이번 후보의 새 PASS로 기록하지 않는다.
- 이번 후보의 Windows 실행, v1.8.11 업데이트, 데이터·사진·이력·세션 보존, 변경 기능 회귀와 재실행/재부팅은 여전히 필수이며 기존 증거로 대체하지 않는다. 검증판의 별도 설치는 정식판 업데이트 검사를 대체하지 않는다.


## 최신 사용자 배포 지시 반영 — v1.8.12

앞 절의 Windows 필수 재실행·영구 운영 잠금 판단은 당시 상태다. 이후 사용자는 Windows VM·Node·설치·A–I 반복 검사를 중단하고, 변경 영역 검사와 설치 파일·채널 무결성을 확인한 뒤 전국용 배포하도록 승인했다. 이 절이 최신 배포 기준이다. Windows 미실행은 NOT RUN이며 새 버전 실행 PASS로 바꾸지 않는다.

- 영구 배포 차단을 제거하고 현재 학급 연결에 따라 등록 가능 여부를 제공한다. 기본 `enabled=false`는 연결 전 상태다. 연결 후에도 main의 등록된 세션/학급 계약, 실시간 권한·대상 관찰, 최종 내용/원본 대조와 교사 최종 승인 모두 필요하다. 다른 학급 이동·만료·선택 변경 시 차단한다. 개발 시험 승인은 운영 권한으로 사용하지 않는다.
- 변경 영향 단위 41개 PASS. 실제 main→preload→알림장 UI 연결 검사 PASS: 학급 확인 전 차단, 확인한 학급에서만 버튼 활성, 다른 학급 이동 시 즉시 무효화. HTTPS를 격리한 로컬 검사이며 실서비스 게시 PASS가 아니다.
- 기존 실서비스 테스트 학급 전체 완주와 일반 학급 비게시 성공은 해당 기록의 환경/커밋에만 적용한다. 새 일반 운영 연결의 실서비스 재확인은 NOT RUN. 실제 학생·학부모 대상 시험 게시, 예약, 임시저장 0회.
- 이번 릴리스 Windows 실행·업데이트·데이터/세션 보존·재부팅은 NOT RUN. 기존 설치 코드 증거와 Mac 회귀 및 패키지 무결성을 재사용/검증한다. 잔여 위험은 Windows 실행 및 서비스 UI 변화이며 확인되지 않은 항목은 차단한다.
- 전국용만 1.8.12로 준비한다. appId/사용자 데이터 경로/NSIS 업데이트 보존 코드와 옥구초 배포 채널은 변경하지 않는다. Actions 신규 실행 없이 로컬 빌드한다.
