# 학교종이 앱 버튼 연결 후속 검증

기준 HEAD `fe3784d9f511577264aef28066ee07a93a73848f`, 브랜치 `feature/schoolbell-diary-nationwide`, Draft PR #5 / Issue #4. 이전 A/B/C 기록은 보존하며 이번 검사의 PASS로 재사용하지 않는다.

**앱 실서비스 전체 흐름 BLOCKED / 운영 잠금 유지 / 출시 NO GO.** 별도 시험 데이터로 개발 앱을 열었으나, 앱 내 직접 로그인 요청에 사용자가 현재 진행할 수 없다고 답했다. 다시 로그인을 요구하거나 외부 브라우저 세션을 추출·복사하지 않았다. 기존 로그인 브라우저에서 필요한 읽기 관찰만 이어 갔다. 이전에 승인된 합성 사진 비게시 업로드 범위에서 미리보기 다운로드 경로도 확인했다. 새 게시 조작은 0회다.

## 새로 연결한 코드

- `schoolbell-live-context.cjs`: 실제 관찰한 학급정보/계정/학생명단/초대 화면을 앱의 동일 세션을 사용하는 임시 창에서 읽는다. 외부 브라우저 쿠키, 비밀번호, 인증코드를 다루지 않는다. 학급 경로와 종류, 이름에 표시된 학년·반, 명단의 채워진 입력란 수를 검사한다. 학교·학년도·계정의 고유 신원·교사 권한·실제 가입자 수·필수 관리자 알림은 별도 미확인으로 반환한다.
- `schoolbell.cjs`, `preload.cjs`, `diary-schoolbell.js`: 읽기 전용 `schoolbell:inspect`와 **로그인 후 실제 화면 확인** 버튼. renderer에는 고정 안내와 불리언만 전달한다. 이 검사는 검증된 연결/권한 승인/성공 이력을 저장하지 않는다. 취소·시간 초과 시 임시 읽기 창만 닫으며 교사의 작성 창과 초안은 보존한다.
- `schoolbell-live-posts.cjs`: 실제 `app-letter-item-long` 부모의 `div.notification-post[data-letter-id]`와 날짜 tooltip의 `aria-describedby`를 읽는다. 표시된 달력 날짜를 엄격하게 검사하고 잘못된 날짜나 중복 ID를 거부한다. 게시 재조회 시 원래 학급으로 다시 이동하고 제목이 유일한 게시물의 ID/날짜/범위를 기존 원본 다운로드 검증에 전달한다.
- 목록은 `virtual-scroller`이고 전체 끝/총수 근거가 확인되지 않았다. 보이는 게시물 ID는 수집하되 `complete:false`를 반환한다. 빈 footer나 보이는 4개를 전체 목록으로 간주하지 않는다. 따라서 원격 중복 조회는 아직 완료되지 않았다.
- `schoolbell-electron-driver.cjs`, `schoolbell-prepared-driver.cjs`, `schoolbell-observed-post.cjs`: 초안 제목과 고정 학급 binding을 읽기 공급자에 전달하고, 파일 다운로드 전후에도 같은 게시물 ID인지 확인한다. 기존 단일 게시·pending 선저장·본문/원본 해시·순서 대조·성공 증거 우선 저장·변경되지 않은 초안 전환 계약은 유지한다.
- production capability와 공식 권한 기본값, 버전, appId, 전국용/옥구초용 배포 채널은 변경하지 않는다. 하이클래스 구현 파일도 변경하지 않는다.

## 실제 화면에서 확인한 범위

| 항목 | 이번 결과 |
|---|---|
| 게시물 ID | PASS 읽기 관찰 — 기존 합성 C의 부모 속성 ID와 이전 링크 복사 ID 일치. 실제 값은 저장소에 기록하지 않음 |
| 게시 표시 날짜 | PASS 읽기 관찰 — 새 `readPostIndex`를 실제 DOM에 실행해 `2026-11-09` 읽음. 본문/계정/다른 게시물 내용 수집 없음 |
| 목록 완결성 | BLOCKED — 가상 스크롤에 표시된 4개와 빈 footer 외에 전체 범위 증거 없음 |
| 명단 입력란 | PASS 집계 관찰 — 실제 readContextScreen에서 30개 빈 슬롯, 이름/보호자1/보호자2/학생 연락처 값 각각 0건. 가입 인원으로 해석하지 않음 |
| 학교·학년도·교사 권한 | BLOCKED — 관찰한 독립 학급정보 화면에는 학교/학년도가 확인되지 않음. 이름 변경 양식·기본 프로필 이미지·관리자 카드 존재는 고유 로그인 신원 증거가 아님 |
| 게시 전 원본 | BLOCKED — 가상 PNG 1장을 비게시 작성폼에 업로드하고 미리보기의 v5 iframe/ion-item 파일 컨트롤을 관찰. 해당 컨트롤의 브라우저 조작은 대상 오류로 종료되어 다운로드 없음. 서비스가 다운로드를 금지했다고 단정하지 않음 |
| 날짜 의미 | BLOCKED — 작성 화면의 날짜 입력 컨트롤을 확인하지 못함. 게시 후 표시 날짜/PC 시각으로 앱 작성 날짜를 대체하지 않음 |

이전 문서의 “본문 DOM 자체에 ID 근거 없음”은 당시 조사 범위다. 이번에는 카드 **부모** 속성을 확인해 ID 수집을 구체화했다. 이전 감사 문서를 덮어쓰지 않는다. 미리보기 v5 관찰만으로 메인 창의 공식 호스트 허용 범위를 확대하지 않는다.

## 앱 전체 흐름 판정

| 단계 | 상태 | 이유 |
|---|---|---|
| 앱 버튼 → 실제 입력/첨부 | BLOCKED | 앱 직접 로그인 미완료, 자동 권한/날짜/게시 전 원본/목록 범위도 미완료 |
| 앱에서 실제 게시 | NOT RUN (BLOCKED) | 위 조건 미충족. 이번 새 게시 승인·조작 없음 |
| 앱에서 서버 재조회 | NOT RUN (BLOCKED) | 기존 합성 글의 브라우저 읽기만 확인. 앱 publisher가 생성한 실제 게시물 없음 |
| 앱 성공 이력 → 초안 처리 | NOT RUN (BLOCKED) | 실서비스 성공 증거가 없어 이력 성공/초안 초기화하지 않음 |

앱 로그인만 완료하면 바로 게시 가능한 상태라고 주장하지 않는다. 대상·권한과 날짜 의미, 게시 전 독립 원본, 원격 전체 목록 증거 및 원자적 재검사가 먼저 완성되어야 한다. 그 후 앱에서 합성 초안을 사용하고 실제 게시 직전에 별도 승인을 받아야 한다. 공식 운영 허용/최종 활성화 승인도 별도 조건이다.

## 검사와 운영

검사 수치와 Windows 환경 결과는 같은 작업의 최종 manifest 및 로그에 기록한다. 합성 검사는 실서비스 PASS로 바꾸지 않는다. 초기 URL 쿼리 허용 결함을 단위 검사에서 발견해 수정했으며 실패 로그도 보존한다.

GitHub 신규 실행을 요청하지 않았다. 현재 브랜치 workflow blob `58613481272e59545c0c910d5d6e033a65f0247a`는 다른 Windows 개발 브랜치 push와 수동 dispatch만 구독한다. PR/현재 브랜치 push 트리거 없음. Actions 확인 시 총 19회/마지막 41977391612. 유료 자원·신규 VM·결제/권한/워크플로 변경 없음. 합성 자료와 수정 소스만 기존 VM 임시 시험 폴더에 사용한다. 실제 계정·명단·학급/게시물 ID·세션·학생 사진을 GitHub에 포함하지 않는다.
