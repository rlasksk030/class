실제 조회 대상은 기존 합성 시험 C만이다. 다른 게시물은 목록의 중복 없는 ID를 메모리에서 세고 종료 표식을 확인했으며 본문/원본을 열지 않았다. 기존 사용자 작성 글은 수정·삭제하지 않았다. 기록에는 계정, 학교/학급/게시물 ID, URL, 쿠키, 실제 본문·사진이 없다.

## 실제 오류와 수정

기존 원본 reader는 첨부 파일을 펼칠 때 `.d-flex.align-items-center.cursor-pointer` 배치 컨테이너 자체를 클릭했다. 실제 앱에서 이 클릭은 파일 목록을 열지 않았고, 파일 행의 부모가 `display:none`으로 남아 다운로드 전 검증에서 중단됐다. 기다리는 것과 백그라운드 갱신만으로 해결되지 않았다.

실제 화면의 **첨부파일 (2)** 문구를 누르면 파일들이 나타나는 것을 관찰했다. 기존 컨테이너 안의 이 문구를 가진 유일한 가장 안쪽 요소를 클릭하도록 수정했다. 펼친 뒤에는 모든 파일 행이 표시될 때까지 제한 시간 안에서 재검사한다. 중복 요소·누락·순서 변경·미표시는 계속 실패 처리한다. 다운로드는 기존 `will-download` 경로와 동일 앱 세션을 사용하고 임시 원본은 검사 후 삭제한다. 비공개 API/쿠키/인증정보 추출은 없다.

`schoolbell-readback.cjs` 및 읽기 전용 IPC를 추가해 **알림장 → 학교종이 → 기존 게시물 조회 확인 → 현재 초안으로 게시물 조회**로 공유 baseline reader를 실제 앱에서 실행할 수 있게 했다. 현재 초안의 제목과 같은 게시물만 본문·사진을 읽는다. 이 조회는 등록 영수증, 연결 권한, 운영 잠금 또는 초안 초기화를 변경하지 않는다. 개발 시험 프로필에만 개인정보 없는 개수/날짜/해시/오류 위치 진단 파일을 남긴다.

## 날짜·권한에 대한 정확한 잔여 조건

- 실제 작성 화면: 날짜 기본 제목, 보내기 드롭다운의 `즉시발행하기`/`예약발행하기` 관찰. 날짜 입력란은 확인되지 않음. 예약 기능은 구현/선택하지 않았다.
- 앱 작성 날짜는 로컬 초안 날짜다. 제목의 날짜나 PC 시각을 학교종이 발행 날짜로 취급하지 않는다. 게시 후 날짜는 서버가 다시 보여 주는 게시물 날짜로 검증한다. 현재 게시 전 guard는 **확인된 학교종이 발행 날짜가 초안 날짜와 같을 것**을 요구하며, 이를 제공하는 실사이트 근거가 없어 차단을 유지한다. 임의 날짜/HTML/추측 선택자로 우회하지 않았다.
- 학급 목록에 관리자 역할 문구는 표시된다. 그러나 현재 코드의 계정 이름·기본 아바타 비교만으로 고유 로그인 본인과 특정 학급의 필수 관리자 수신자가 같다고 증명할 수 없다. 이를 권한 PASS로 올리지 않았다.
- 독립된 학교/학년도 근거, 본인과 필수 관리자 연결, 게시 전 사진 원본 reader, 최종 게시 직전 guard 및 신규 게시 성공 영수증→변경 없는 초안 초기화의 실제 완주가 남았다. 이 조건을 충족한 뒤 구체적인 대상·내용·사진을 제시하고 새 게시마다 별도 승인을 받아야 한다.
- 공식 서비스 자동화 허용 근거가 새로 확보된 것으로 기록하지 않았다. 이전 사용자의 합성 업로드 허용/게시별 승인과 운영 해제 승인을 혼동하지 않는다.
