## 순서와 진행 조건

1. 기존 코드·검증 문서·공식 공개 자료 확인.
2. 교사가 직접 로그인하여 담당 학급의 빈 알림장 작성 화면을 연 뒤, 입력·첨부·날짜·발행 컨트롤 구조만 관찰한다. 기존 학급에서 입력·업로드·게시하지 않는다. 학생·학부모 정보, 기존 게시물, 세션, DOM 전체 덤프를 수집하지 않는다.
3. 실제 DOM 드라이버는 관찰한 구조와 명시적 자동화 허용 근거가 확보된 범위에서 구현한다. 허용 근거가 없으면 실서비스 입력·발행을 잠근다. 쿠키 추출·비공개 API 호출·인증 우회는 사용하지 않는다.
4. 화면 확인과 별도로 승인된 테스트 학급 및 실제 수신자 부재를 확인한다. 승인 범위 안에서만 합성 문구·가상 사진 0/1/여러 장을 한 번씩 게시하고, 재조회한 본문·사진 원본·순서를 대조한다. 불확실한 결과는 재시도하지 않는다.
5. 선행 조건을 기다리는 동안 공통 편집기의 검증 성공 후 이력 저장·새 초안 준비 처리를 완성하고 로컬 합성 시험으로 초안 보호를 확인한다. 이 결과는 실제 서비스 PASS가 아니다.
6. 변경 영역 검사 후 필요한 전체 로컬 회귀를 한 번 수행한다. Windows 검사는 별도 증거로 구분한다. 실제 서비스 차단과 미검증 범위를 문서화한다.
