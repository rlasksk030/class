## 실제 앱 상태와 이번 범위

앱의 현재 접근성 화면은 학교 설정/검색 화면이었다. 앱 내부 학교종이 로그인 창과 등록 버튼은 보이지 않았다. 로그인 세션을 인증된 상태로 확인하지 못했다. 사용자가 지금 직접 로그인할 수 없다는 답변을 재사용했고 다시 요청하지 않았다. 외부 브라우저 쿠키·인증정보를 복사하지 않았다. 이번 실서비스 신규 입력/첨부/게시/서버 재조회 0회, 실제 계정이나 학생 자료 캡처·저장 없음.

이번에는 이전의 목록/파일 컨트롤 재조사나 A/B/C 재게시 대신, **기본 Electron 드라이버의 최종 DOM guard가 공급되지 않았던 연결부**를 구현했다. 기존 공통 알림장 버튼 → IPC → publisher → prepared driver → Electron 조작 → 성공 증거 저장 → 공통 편집기의 초안 완료 경로를 분석하고 유지했다.

## 연결한 동작

- `schoolbell-final-guard.cjs`: 같은 학교·학년도·학년·반·게시판·계정에 연결된 최신 main-process 신원/권한/수신대상/날짜 증거를 요구한다. 사진은 UI에서 다시 받은 원본 바이트를 해시·길이·순서로 대조하고 그 증거를 **현재 문서 revision**과 같은 시도에 묶는다. 파일명이나 미리보기만으로 통과하지 않는다.
- `schoolbell-electron-driver.cjs`: 기본 guard 및 증거 생성 경로를 연결했다. 신원/날짜/원본 읽기가 실패하면 이전 결과를 재사용하지 않는다. main-frame 탐색·같은 URL 새로고침·renderer 종료 시 증거를 폐기한다. 탐색 중 반환된 신원/날짜/업로드 결과도 거부하고 종료 시 listener를 해제한다. 검증 중 수집한 이름/계정 원문은 저장·로그하지 않는다.
- `schoolbell-observed-composer.cjs`: DOM 조작 전에 main 증거를 결합하고 기존 허용/취소 검사를 다시 수행한다. 실제 관찰된 작성 경로·학급 ID·유일한 작성폼·발행 대상 표기·열린 대상/미리보기 모달·업로드 완료/파일 순서·본문/제목/revision을 보내기와 같은 DOM 작업에서 확인한다. 문서마다 임의 token을 붙여 같은 URL의 새 문서에서 옛 revision을 재사용할 수 없게 했다. 본문은 기존 native 일반 텍스트 입력을 유지한다.
- `schoolbell-audience.cjs`, prepared driver: 학생/학부모 대상 0과 필수 관리자 본인 알림을 분리했다. 필수 관리자가 있으면 현재 교사 본인만 수신한다는 최신 **실제 UI 근거**, 다른 대상 0, 관리자 1명, 같은 계정·학교·학급·게시판에 한정된 명시적 main 권한이 모두 필요하다. 사용자 입력이나 빈 표만으로 이 조건을 승인하지 않는다. 현재 live provider에는 신원/본인 알림 근거가 없어 계속 차단된다.
- 수신대상 의미·역할·대상 표기와 알림 종류를 시도 전체에 고정했다. 나중에 각각 유효한 대상이라고 하더라도 처음 승인한 대상에서 바뀌면 보내기를 차단한다. 본인 관리자 알림이 실제 검증된 경로에서는 최종 앱 확인창에 본인 알림 가능성을 표시한다. 권한은 DOM 실행 직전에도 재검사한다.
- 실제 A/B/C에서 관찰한 단일 보내기 동작을 runtime의 `finalAction: single-send`에 연결했다. 별도의 앱 최종 확인, 게시 시도 선소비, 단일 클릭, 불확실 시 재전송 금지는 그대로다. 추가 서비스 확인창/예약발행/임시저장 성공을 추측하지 않는다.
- 성공 증거는 기존 publisher가 디스크 이력에 먼저 저장한다. 공통 편집기는 해당 저장된 영수증을 다시 대조한 뒤 변경되지 않은 초안만 비운다. 이 편집기/저장/백업 로직은 이번에 변경하지 않았으며 새 실서비스 성공 없이 초안을 초기화하지 않았다.

## 날짜 규칙: 앱 정책과 실제 서비스 의미 구분

앱 정책은 **검증된 서비스 UI의 게시 달력 날짜 = 앱 작성 날짜**일 때만 입력/게시 허용이다. 증거에는 `verified`, `source: observed-service-ui`, `meaning: publication-calendar-date`, 유효한 `value`, 같은 학교/학급/계정 scope와 최신 `observedAt`이 필요하다. PC 시각, 앱 날짜, 제목 문구, 게시 후 tooltip을 게시 전 날짜 근거로 대체하지 않는다. HTML/본문 서식/추측한 날짜 선택자를 추가하지 않았다.

**학교종이의 실제 게시 전 날짜 의미/조작 규칙을 확정한 것은 아니다.** 현재 runtime의 날짜 provider는 계속 `verified:false`다. 게시 후 날짜 tooltip 관찰만으로는 이를 바꾸지 않았다. 실제 UI에서 근거를 확보하고 위 계약에 연결하기 전에는 첫 제목 입력부터 차단된다.

이전의 ‘기본 최종 DOM guard 미연결’은 이번 코드 연결로 갱신한다. **학교/교사/날짜의 실제 UI 검증 자체가 완료된 것은 아니다.** `identityVerified`, `authorityVerified`, `classApproved`, `testClassApproved`, `recipientsVerified`의 live 기본값 false, 기본 permission 없음, `capability.enabled=false`는 유지한다. renderer/설정/환경변수로 승인하는 경로를 만들지 않았다. 공식 운영 허용 및 최종 활성화·배포 승인도 아직 확보된 것으로 취급하지 않는다.

다음 실제 시험은 앱 직접 로그인 후 현재 학급에서 학교·학년도·고유 교사 권한 근거와 게시 날짜 정책을 확인해야 한다. 필수 관리자와 현재 교사가 같다는 UI 근거 및 본인 알림 승인을 같은 scope에 묶고, 비게시 원본/목록 조회를 먼저 검증한다. 그 뒤 새 앱 완주 게시를 별도로 최종 승인받는다. 기존 A/B/C는 다시 실행하지 않는다.
