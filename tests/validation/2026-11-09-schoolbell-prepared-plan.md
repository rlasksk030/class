# 학교종이 자동 등록 사전 구현 계획

기준 HEAD `ea107d6e13e75d33da7fd0a1f2cdd1f0ae352adb`, `feature/schoolbell-diary-nationwide`, Draft PR #5 / Issue #4. 사용자 요청: 공식 문의 초안 작성과 허용 전 가능한 코드·합성 검증 완료.

1. 실제 화면 관찰 기록과 읽기 전용 probe를 재사용한다. 구조 확인을 위해 실사이트를 다시 조작하지 않는다.
2. 기술 문의 초안을 파일로 작성한다. 발송·서비스 신청·결제는 하지 않는다.
3. 기존 게시 처리기에 맞는 사전 드라이버를 구현하되, 미관찰 UI는 명시적 bridge 검증 계약으로 분리한다. 운영 gate와 driver=null은 유지한다.
4. 권한·대상·날짜·첨부 원본/순서·최종 조작·재조회 조건을 집중 단위 검사와 격리된 로컬 Electron 사이트로 검증한다.
5. 변경이 안정된 뒤 전체 구문/단위/Electron 회귀를 한 번 실행한다. 동일 전체 검사를 이유 없이 반복하지 않는다.
6. Windows의 현재 상태를 읽기 전용으로 재확인한다. 기존 VM이 사용 가능하면 임시 시험 폴더에서 검사하고 원래 상태로 돌린다. 새 VM·설치 파일·빌드·배포는 만들지 않는다.
7. 미검증 조건과 실패 기록을 보존하고, Actions 트리거를 확인한 뒤 기존 승인 범위의 개발 브랜치와 Draft PR에 반영한다.

테스트 학급에 학생·학부모가 현재도 없다는 사용자 답변을 이번 요청에서 다시 받았다. 이 답변을 자동 DOM 인원/권한 대조의 성공으로 취급하지 않는다. 실사이트 입력·첨부·최종 게시 조작은 이번 범위에서 0회다.
