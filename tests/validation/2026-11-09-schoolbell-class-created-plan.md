# 학교종이 학급 개설 이후 계획

- 원격 기준은 `2463ea6ad7692f458fa191ec872bcb42a2f5a7c6`, 기존 로컬 작업 `06d0cf7`까지 보존한다.
- 학급은 **사용자 개설 확인**으로 상태를 갱신한다. 실제 화면에서 승인·교사 권한·수신자 없음까지 확인한 상태와 구분한다.
- 현재 Work 설정에서 로컬 브라우저 사용이 꺼져 있어 UI 접근이 차단되었다. 연결 가능한 PC 화면의 직접 로그인을 기다린다. 비밀번호·인증코드를 받거나 다른 방법으로 우회하지 않는다.
- 사용자의 최종 답변은 **학교종이 공식 허용 답변 없음**이다. 앞선 선택형 응답을 허용 증거로 사용하지 않는다.
- 접근 가능해지면 학교/학급 → 알림장 → 빈 작성 화면 순서로 필요한 컨트롤만 관찰한다. 개인 정보·기존 게시물 전체 캡처/로그를 남기지 않는다. 관찰한 구조와 허용 범위 안에서만 비게시 입력·첨부 시험 및 실제 드라이버를 구현한다.
- 실제 발행은 공식 허용, 승인된 학급, 실제 수신자 없음, 외부 알림 없음, 합성 자료 조건을 모두 확인하고 **별도 사용자 승인 후** 수행한다.
- 지금 가능한 구현은 기존 처리기가 검증한 게시물 ID·게시판 ID·사진 원본 해시/순서·검증 시각을 저장하고, 이 증거가 없는 성공 응답으로 초안을 초기화하지 않도록 하는 것이다. 실제 UI 드라이버 또는 실서비스 PASS로 표시하지 않는다.
- 변경 영역 단위/화면 검사 후 필요한 회귀를 새로 실행한다. 기존 Windows 환경의 상태만 확인하며 새 VM을 만들지 않는다.
- 원격 PR 갱신 전 현재 브랜치와 대상 브랜치의 Actions 트리거를 확인한다. 자동 실행 없음이 확인되면 검증된 변경을 Draft PR #5에 반영한다. 워크플로·요금제·버전·배포 채널은 바꾸지 않는다.
