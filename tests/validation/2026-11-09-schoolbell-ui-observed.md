## 진행 범위

사용자가 연결된 브라우저에서 직접 로그인하고 새 학급 화면을 열었다. 빈 알림장 작성 화면, 학생명단, 학급정보를 읽기 전용으로 확인하고 빈 작성 화면으로 돌아왔다. 제목·본문 입력, 파일 선택/첨부, 임시저장, 미리보기, 보내기 버튼 조작은 하지 않았다. 최종 확인을 보기 위해 보내기를 누르지 않았다.

비밀번호·인증코드·쿠키·세션·비공개 API를 사용하거나 추출하지 않았다. 계정/학교/학급 식별값·학생/학부모 이름·명단 내용·기존 게시물 본문·전체 화면 캡처를 증거 파일이나 GitHub에 남기지 않았다. 구조 검사 결과에는 정해진 상태값·개수·불리언만 포함한다.

## 실제로 관찰한 구조와 구현

합성 페이지 선택자를 가져오지 않고 실제 DOM에서 다음 구조를 확인했다.

| 용도 | 관찰한 선택자/속성 |
|---|---|
| 작성 화면 범위 | `app-boards-write` |
| 제목 | `input[placeholder="제목을 입력해 주세요."]` |
| 본문 | `div.fr-element.fr-view[contenteditable="true"]` |
| 첨부 | `input[type="file"]`, `multiple`, accept에 JPG/JPEG·PNG·HEIC/HEIF 등 포함 |
| 보내기 | `button.btn-with-description`, 공백을 제거한 문구가 `보내기`로 시작, 빈 글에서 disabled |
| 임시저장 | 작성 화면의 button 중 문구 `임시저장` |

`app/schoolbell-ui-probe.cjs`는 이 구조만 읽는 독립 함수다. 현재 화면에서 제목·본문·파일·보내기·임시저장 컨트롤이 각각 1개인 것을 동일 함수로 대조했다. 중복/누락 시 첫 번째 요소를 임의로 선택하지 않는다. 입력값·본문·파일 객체·URL·식별정보를 반환하지 않는다. 날짜·권한·대상·첨부 성공은 항상 미검증이며 `publishReady=false`를 반환한다. accept 속성은 선택 가능 형식의 표시일 뿐 업로드 성공 증거가 아니다.

**이 함수는 실제 입력/첨부/게시 드라이버가 아니다.** Electron/IPC/production publisher에 연결하지 않았다. 기존 `schoolbell-publish.cjs` 처리기, `driver=null`, `capability.enabled=false`, 하이클래스, 이력·중복 방지·초안 보존, 버전·appId·배포 채널을 변경하지 않았다. 향후 승인된 실서비스 드라이버에서 사용할 읽기 전용 구성 요소만 추가했다.
