## ① 공식 자동화 허용

[기술 문의문 초안](../../학교종이_자동화_기술문의_초안.md)을 작성했다. 교사 본인 계정 연동, Electron UI 자동화, 제목/본문 입력, 사진 첨부, 최종 게시, 공식 API/승인된 무료 방식, 테스트 학급 승인·알림 조건을 항목별로 묻는다. **미발송**이며 수신처·최종 문구에 대한 사용자 승인 전에는 발송하지 않는다. 유료 게시판 연동 서비스 신청·결제·약관 동의 없음.

공식 허용 근거는 아직 확보되지 않았다. 공개 매뉴얼이 있다는 사실이나 사용자의 학급 개설/수동 게시 성공을 자동화 허용으로 바꾸지 않았다. 이번 작업은 기존 관찰 결과를 재사용했고 실사이트 DOM 검사를 반복하지 않았다. 실제 학교종이에 대한 입력·첨부·발행 조작은 0회다.

## ② 구현

- 기존 읽기 전용 probe와 실제 관찰 선택자를 재사용했다. 필수 요소가 없거나 중복되면 첫 요소를 임의로 조작하지 않고 차단한다.
- `schoolbell-prepared-driver.cjs`가 기존 게시 처리기 계약을 구현한다. 학교/학년도/학년/반, 현재 교사 권한과 학급 승인, 동일 계정/화면, 승인된 시험 학급, 학생/학부모 0명, 외부 알림 없음, 증거의 최신성을 검증한다.
- 날짜 미확인·존재하지 않는 날짜·수정 불가능한 불일치는 첫 제목/본문 입력 전에 차단한다. 미관찰 날짜 선택자는 만들지 않았다.
- 업로드 완료 후 독립적으로 받은 원본 바이트의 SHA-256/길이/순서를 대조한다. 파일명·미리보기·주장된 해시만으로 성공 처리하지 않는다. 일부 실패·대기·순서 반전·원본 변형은 최종 게시를 막는다.
- 입력/첨부 직전 대상 및 승인 철회를 다시 확인한다. 최종 조작 bridge에는 전체 내용·사진·revision·대상과 승인 확인 콜백을 전달한다. 조작 시도를 먼저 소모해 실패/불확실한 클릭을 재시도하지 않는다.
- 완료된 기존 게시물 조회와 중복 판정에 제목·본문·날짜·사진 내용 및 순서를 사용한다. 게시 후 전체 재조회에서 기존 ID 밖의 정확히 1개 결과와 모든 내용/원본이 일치해야 성공한다.
- 기존 성공 증거 저장·이력·공통 편집기의 초안 전환을 재사용한다. 증거 저장 실패·불확실 결과·등록 중 편집·다른 날짜/학급·새 사진은 기존 규칙에 따라 보존한다.
- 오류는 고정된 안전한 이유만 반환한다. 원격 예외 문구·계정·본문·URL은 사용자 오류 메시지에 넣지 않는다. 종료가 완료되지 않으면 publisher를 잠가 겹친 작업을 막는다.

`schoolbell-driver-errors.cjs`의 오류 안내만 기존 처리기에 연결했다. 실제 driver 생성·운영 IPC·capability 변경은 하지 않았다. `schoolbell.cjs`의 driver=null과 코드 소유의 enabled=false 유지. 하이클래스·사진 저장/백업·appId·버전 1.8.11·전국용/옥구초용 배포 채널은 변경하지 않았다.

전체 회귀에서 드러난 작은 창의 타이머 종료 알림 겹침도 수정했다. `extras.css`에서 열린 타이머 dialog 안의 알림만 문서 흐름에 배치해 닫기 버튼을 가리지 않게 했다. 창 밖 종료 알림 위치와 타이머 상태/음향/저장 로직은 유지했다. 900×550에서 닫기 버튼·Escape·native close 검증을 명시적으로 수행했다.

## ⑥ Windows

과거의 Parallels Service 접근 실패를 이번 차단 사유로 그대로 재사용하지 않았다. 호스트 권한으로 기존 VM 조회가 가능했고, 기존 Windows VM을 suspended → running으로 재개하는 데 성공했다. 그러나 Node/시험 폴더를 조회하는 읽기 전용 게스트 명령이 2분 이상 응답하지 않았다. 제가 시작한 해당 대기 프로세스만 종료하고 VM을 suspended로 복구했음을 재확인했다.

현재 Windows 차단은 **게스트 명령 실행 경로 무응답**이다. 현재 소스의 Windows 구문/단위/E2E·설치·재부팅·클립보드는 NOT RUN이다. 이전 Windows PASS를 재사용하지 않는다. Guest Tools 업데이트·VM 신규 생성·복제·설치·빌드·재부팅·사용자 데이터 변경은 하지 않았다. 다음 검사에는 기존 VM의 게스트 실행 경로 복구 또는 사용자가 제공하는 정상 Windows 검사 환경이 필요하다.
