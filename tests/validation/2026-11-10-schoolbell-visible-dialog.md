## 실패 조건과 이번 실제 관찰

기존 수신대상 검사는 DOM의 모든 `mat-dialog-container` 중 대상 컴포넌트가 있는 개수를 셌다. 생성 전, 표시 애니메이션 중, 숨겨진 잔여 창, 실제 유효 창을 구분하지 않았다. 기존 게시 후 실패는 `recipientTableEmpty=false → testFacts=false → context-unverified`와 `dialog-count`까지 확인됐고, 당시 0개/복수 여부는 기록되지 않았다. 과거의 정확한 창 개수를 사후에 단정하지 않는다.

이번 실제 앱 진단에서는 다음 전환을 확보했다. 원문·명단·계정·학급 ID를 기록하지 않고 개수와 상태만 남겼다.

1. 변경 버튼 준비 완료, 대상 창 0개.
2. 열기 1회 후 잠시 DOM 0개.
3. DOM 1개지만 숨김 상태 1개, 유효 창 0개.
4. 유효 창 1개지만 로딩에 가려져 검사 불가.
5. 가림 해제 후 창 1개에서 검색 없는 빈 구성원 표·필수 관리자 확인.
6. 닫기 후 DOM 1개 → 0개, 작성 화면 컨트롤 준비 완료.

목록 화면의 비게시 검사 PASS 후 작성 화면 연결 승인 준비가 한 차례 일반 오류로 중단된 것도 남긴다. 이 최초 실패의 세부 로그는 없으며, 진단을 보강한 뒤 위 실제 상태 전환과 승인 전후 검사를 확인했다. 과거의 모든 실패를 숨겨진 잔여 창 때문이라고 주장하지 않는다.

## 최소 수정 범위

- `schoolbell-recipients.cjs`: 렌더링 크기, 조상 display/visibility/opacity, hidden/inert/aria-hidden을 확인해 비표시 창을 제외한다. 보이는 창이 복수이거나 상태를 확인할 수 없으면 즉시 차단한다. 한 창이 로딩에 가리면 기다린다. 열기는 한 번뿐이며, 닫힌 뒤 작성 화면 버튼이 다시 조작 가능해질 때까지 기다린다.
- `schoolbell-live-context.cjs`: 대상 창 개수·표시/숨김/가림 및 단계 진단을 전달한다. 기존 학교·학급·권한·학생/학부모 없음·관리자 확인 조건은 유지한다.
- `schoolbell.cjs`: 개발 시험 프로필에서만 개인정보 없는 단계 진단을 기록한다. 운영 허용, publisher, native 보내기, 원본 비교, 성공/초안 처리 로직은 변경하지 않는다.

미확인 값을 true로 바꾸지 않았다. 사진·제목·본문 입력, 게시 ID 집합 대조, 원본 다운로드, 단일 게시, 성공 이력 및 초안 처리, 기존 조회 전용 reconciliation을 재구현하지 않았다.
