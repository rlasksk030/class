# 학교종이 자동 등록 후속 구현·검증

Issue #4 / Draft PR #5 / feature/schoolbell-diary-nationwide. 기준 f9ea20170a3249b3695b934d60ce6a171af3f760. [계획](2026-11-06-schoolbell-automatic-plan.md), [이전 구현 검증](2026-11-06-schoolbell.md), 이전 실패·성공 로그는 보존한다.

## 현재 판정

**실제 학교종이 자동 등록은 BLOCKED / 정식 배포 NO GO.** 허용 여부와 실제 학급 화면·게시 확인이 미검증이다. 자동 등록 처리기와 합성 웹 화면 검증은 구현했지만, 실제 학교종이 DOM 드라이버는 구현/연결하지 않았다. 사용자가 원한 한 번의 실제 등록이 완성되었다고 주장하지 않는다. 수동 발행은 임시 대체 기능이다.

사용자는 공식 허용 답변이 없다고 확인했다. 이후 테스트 계정은 준비했으나 학급 개설/승인이 며칠 걸릴 수 있다고 알려 왔다. 계정/비밀번호를 전달받거나 읽지 않았고, 학급이 없는 계정으로 게시를 시도하지 않았다. 실제 학부모·학생 대상 발행 0회.

공식 도메인 한정 API/자동화 검색도 실시했으나 공개 게시 API 명세·제휴 계약·UI 자동화 승인 답변을 확보하지 못했다. 비공개 제휴 API가 없거나 UI 자동화가 기술적으로 불가능하다고 단정하지 않는다.

실제 공개 사이트에서 HOME → v4의 gate/home → 로그인 버튼 → gate/login 이동을 관찰했다. 로그인 화면에는 전화번호·비밀번호, 로그인 상태 유지, 웨일 스페이스 로그인 항목이 있다. 어떤 값도 입력하지 않았다. 관찰된 이동은 다음 형태다.

- https://v4.schoolbell-e.com/ko/gate/home?return_uri=https:%2F%2Fschoolbell-e.com%2Fko%2Fmain
- https://v4.schoolbell-e.com/ko/gate/login?return_uri=https:%2F%2Fschoolbell-e.com%2Fko%2Fmain

기존 URL 검사에서 모든 query를 막아 정상 로그인 이동도 차단할 수 있는 문제를 수정했다. 위 gate 경로와 공식 공개 main 반환 주소 한 개만 탐색 중 허용한다. 학급 연결 저장 시에는 query, 로그인/게이트/공개 홈을 계속 거절한다. 저장된 주소도 창을 열 때 재검사한다. 외부 OAuth 경로는 관찰/승인 전까지 확장하지 않는다.

인증 후 담당 학급, 제목/본문 에디터 DOM, 실제 파일 업로드 컨트롤, 최종 발행 확인창, 게시 완료 ID/본문/첨부 증거를 직접 관찰하지 못했다. 따라서 기존 하이클래스처럼 Electron의 분리된 교사 세션에서 웹 UI를 조작하는 방식은 기술 후보로 검토했으나, 선택자나 비공개 API를 추측해 실제 드라이버를 만들지 않았다. 매뉴얼 이미지 3개는 웹 도구 cache miss로 조회하지 못했다. 임시저장·예약발행의 실제 동작과 즉시 게시 결과 대조도 BLOCKED이다.

## 구현한 부분

- 공통 편집기는 유지하고 서비스 이름과 하단 등록 버튼을 구분한다. 학교종이 등록 버튼은 잠김 사유를 표시하고 수동 도우미를 임시 대체 기능으로 명시한다.
- 학교·학년도·학년·반 직접 확인을 대조한다. 이 확인을 실제 교사 권한 검증으로 승격하지 않는다. 기존 학교·서비스·학급별 세션 분리 유지.
- main 소유 capability는 항상 disabled. renderer 입력, 환경변수, 저장 설정으로 자동 등록을 열 수 없다. 실제 드라이버는 null이며 게시 IPC도 원격 접근 전에 BLOCKED를 반환한다.
- 별도 등록 처리기: 서비스/학교/학급/교사 권한 관찰 계약 → 기존 게시 확인 → 대상·내용 사전 확인 → pending 파일 flush/원자 교체 → 작성 화면 → 제목·본문·날짜 → 원본 사진 → 전체 내용/사진 개수·순서 대조 → 단 한 번 게시 → 새로운 게시물 재조회·전체 내용 대조 → success 기록 순서다.
- 결과가 임시저장/예약발행이거나 이전 게시물, 부분 본문/사진, 새로 조회하지 않은 결과면 success로 기록하지 않는다. 본문은 줄바꿈을 보존하고 CRLF 차이만 비교 시 정규화한다. 편집기의 글씨 크기를 외부 서식으로 전송하지 않는다.
- 모든 단계 시간 제한 및 취소 신호, 창/작업을 정리할 수 없으면 해당 처리기를 계속 잠근다. 게시 이후 응답 없음·실패는 불확실 상태로 남고 자동 재시도하지 않는다.
- 자동 시도는 UUID별 기록으로 수동 기록과 분리한다. 불확실한 시도가 있으면 내용 변경 및 수동 전환으로도 재등록을 우회하지 못한다. 직접 확인은 auto-user-confirmed / auto-user-not-posted로 별도 기록하며 auto-success가 아니다. 이전 시도는 삭제하지 않는다.
- 처리기는 기존 초안·사진을 수정하지 않는다. 실제 성공 후 공통 편집기 이력 저장/새 초안 전환 연결은 실서비스 드라이버와 함께 미완료 상태다. 기존 하이클래스의 성공 후 새 초안 및 최신 편집 보존 경로는 그대로 유지한다.

새 서비스 메타데이터가 휴대용 백업에 포함되지 않는 기존 제한도 유지된다. 기존 학생 데이터·사진·로그인 파일·하이클래스 이력·백업을 삭제/재작성하지 않는다.

합성 자동 등록 6건은 사진 1장, 여러 장 원본/순서 및 문자·줄바꿈, 기존 게시 중복, 다른 학급, 서버 저장 결과의 부분 사진 누락과 재시도 차단, 디스크 기록 재개를 검사한다. 테스트 드라이버/서버는 tests/에만 있고 실제 학교종이 주소·API·DOM 선택자를 사용하지 않는다. 합성 PASS는 실제 학교종이 발행 PASS가 아니다.

최초 집중 단위 실행은 중괄호 누락으로 구문 오류가 발생했다. 이를 수정한 뒤 42/42 집중 검사, 최종 전체 97/97이 통과했다. 실패를 PASS에 포함하지 않았다. macOS 원본 로그는 tests/windows/.out/schoolbell-auto/에 보존한다. 기존 감사 기록은 삭제하지 않았다.

macOS 합성 재검사 한 번은 다른 작업 폴더를 가리키던 Electron dist 링크의 실행 파일이 없어 ENOENT로 실패했다. 공식 Electron 40.10.6 arm64 ZIP을 별도 작업 폴더에 내려받고 기존 배포 체크섬 24e3b1a13ff7243f6b9036ebb743b6f62b19e4a925242d27eaa2be90de90a691와 대조했다. 다른 프로젝트의 파일은 수정하지 않았다. 복구 후 합성 6건은 통과했으나 숨겨진 창/검사 연결의 종료가 지연되어 테스트 정리 코드를 보완했다. 이 검사는 앱 종료 기능을 검사하는 것이 아니므로 자신이 실행한 폐기 가능한 Electron 프로세스만 종료하도록 했다. 이전 실패·종료 지연 로그도 보존한다.

Windows는 기존 VM을 재개하지 않고 별도 복사본에서 네트워크 차단 후 소스 Electron으로 실행했다. 수신대상 검사 2개 단언 이후 진행이 멈춰 전체 스크립트는 PASS로 세지 않았다. 임시 VM 재시작 후 실제 암호 입력 화면을 확인하여 인증을 우회하지 않고 나머지 실행을 중단했다. 설치파일 검사, 물리 x64 PC 검사, Windows 전체 검증 완료로 확대 해석하지 않는다. Windows 합성 자동 6건은 마지막 테스트 정리 코드 보완 전 실행 결과이며, 그 정리 코드의 Windows 재실행은 NOT RUN이다. 제품 앱 파일은 동일한 준비용 소스 아카이브를 사용했으며 VM 내부 사후 해시 대조는 로그인 차단으로 BLOCKED이다.

## 별도 검토

구현 후 동일 작업자가 기능 구현과 구분된 검토 단계에서 인증 경계, 저장 실패, URL, 상태 전이, 중복/시간 제한, 기존 데이터 영향을 대조했다. 다른 사람/독립 에이전트의 승인을 받았다고 주장하지 않는다.

검토로 보완한 항목: 정상 공식 login redirect의 좁은 허용, 저장 주소 재검사, 존재하지 않는 달력 날짜 차단, 학년도 대조, 자동 기록 구조 손상 시 차단, 수동 확인으로 success 승격 금지, 종료 확인 실패 시 재실행 잠금. 기존 sandbox/contextIsolation/IPC sender 검사는 유지된다. main의 실제 드라이버는 여전히 없고 합성 드라이버의 활성화 주입은 테스트 코드 전용이다.

미해결: 정책 허용 증거, 승인된 테스트 학급, 관찰된 실제 UI 드라이버, 실제 서버 결과·원본 사진 검증, 성공 후 새 초안 전환의 학교종이 실계정 검증, 실설치 패키지 검증. 이 조건 때문에 출시 판정 NO GO를 유지한다.
