- 학교종이 공식 사이트를 별도의 sandbox/contextIsolation 창으로 열고 직접 로그인하도록 안내. 학교·학년·반 입력 대조와 네이티브 확인 대화상자. 이 결과는 사용자 직접 확인이며 로그인·교사 권한의 서버 검증이 아니다.

- 서비스·학교·학급별 세션과 기록 분리. 기존 하이클래스 링크/해시/쿠키 파일은 보존하며 기존 로그인 저장소는 한 학급만 사용. 신규 메타데이터에는 본문·학생 명단·사진 파일명·비밀번호를 저장하지 않는다.
- 앱 버전, appId, 사용자 데이터 루트, 각 판의 업데이트 공급자·매니페스트·배포 파일은 변경하지 않는다.

## 공식 지원 조사

공식 [웹 매뉴얼](https://schoolbell-e.oopy.io/webmanual)의 [알림장 작성 안내](https://schoolbell-e.oopy.io/1fa563b6-9642-80ab-b7ad-fb6b5c9bdf15)는 학급페이지 → 알림장 → 작성하기, 파일 첨부, 임시저장과 예약발행을 안내한다. [학교페이지/학급페이지 안내](https://schoolbell-e.oopy.io/1f9563b6-9642-806a-a6b2-cfc6979040d8)는 두 페이지의 기본 발행 대상이 다름을 설명한다. [게시판 연동](https://schoolbell-e.oopy.io/board_link)은 학교 홈페이지에서 학교종이로 글을 가져오는 기능이다.

검토한 위 공식 자료와 [이용약관](https://schoolbell-e.oopy.io/terms)에서는 제3자 알림장 게시 API 명세나 외부 자동 등록 허용 근거를 확인하지 못했다. 비공개 제휴 API의 부재를 단정하지 않는다. Issue에 링크된 2025 PDF는 웹 조회 도구의 크기 한도로 읽지 못했고, 공식 사이트가 제공하는 최신 웹 매뉴얼을 확인했다.

**학교종이 자동 발행: BLOCKED.** UI와 main IPC에서 모두 차단한다. 내부 API 호출·로그인 우회·계정정보 수집·실학생 발송·업체 연락은 수행하지 않았다.

전체 실행에서 하이클래스 재연결 검사에 고정 500ms 대기/이전 취소 메시지 재사용에 따른 경합이 발생했다. 연결 완료 신호 및 실제 대화상자 횟수를 기다리도록 테스트를 수정했고 16/16 통과했다. 학교종이 네트워크 실패 검사 추가 후에는 마지막 IPC 검사가 첫 BrowserWindow를 main으로 가정해 원격 창을 선택했고 접근 차단으로 실패했다. main의 file: 창을 명시해 수정한 최종 16/16 결과를 사용한다. 기존 실패 로그는 삭제하지 않았다.

## 유지 및 제한

같은 PC에서 기존 설정·사진을 복원해도 새 서비스 기록은 지워지지 않는다. 새 서비스 메타데이터/로그인 세션은 휴대용 설정 백업에 포함하지 않는다. 다른 PC 복원 시 재연결과 과거 게시물 확인이 필요하다. 공식 로그인·학급·첨부 화면의 호환성과 사이트 변경은 미검증이며, 허용 호스트/저장 가능한 URL 검사를 통과하지 못하면 연결 확인을 중단한다. 앱 밖에서 사용자가 직접 붙여넣거나 게시하는 행위까지 중복 차단할 수는 없다.
