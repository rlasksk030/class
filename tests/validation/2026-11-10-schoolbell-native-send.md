# 학교종이 마지막 보내기 입력 수정

기준 `c1df74dc47559b4b4ee8b936289e5260ef0d1471`, PR #5 Draft, 운영 잠금 유지.

## 확인된 차이와 수정

기존 Electron 구현은 `send.click()`을 호출했다. 이 호출의 반환은 실제 게시 성공 증거가 아니며, 기존 실서비스 시험에서는 완료 화면 이동 및 새 서버 글이 없었다. 이전 A/B/C는 연결 브라우저의 실제 UI 클릭으로 성공했다. 서비스가 어떤 이벤트를 필수로 요구하는지는 아직 확인되지 않았다.

마지막 보내기에만 Electron의 실제 `mouseDown`/`mouseUp` 입력을 사용한다. 기존 입력·첨부·원본 검증은 재구현하지 않았다. DOM click fallback/자동 재시도는 없다. 소유 창의 초점을 확인하고 검증한 단일 버튼의 현재 위치·가림·상속된 비활성 상태를 검사한다. 각 native 이벤트에서 같은 대상, 본문 revision, 내용, 사진, 수신자, 발행 방식 및 만료된 검증 여부를 다시 대조한다. click 이벤트가 실제 trusted down/up 순서로 전달됐는지 확인하며, 그 결과도 게시 성공으로 처리하지 않는다.

전송 뒤 작성 화면·버튼 상태·표시 중 검증 오류/알림·완료 게시판 이동을 구조적 값과 정해진 메시지 종류만으로 기록한다. 임의 사이트 문구, 계정, 학급 식별정보는 진단 파일에 저장하지 않는다. 실제 완료 화면과 독립 서버 재조회·원본 검증이 성공해야 기존 성공 이력/변경 없는 초안 정리로 진행한다.

참고: [Electron sendInputEvent의 창 초점 조건](https://www.electronjs.org/docs/latest/api/web-contents#contentssendinputeventinputevent).

## 이번 검증

변경한 마지막 입력 경로만 격리된 Electron 화면에서 확인했다. DOM click과 trusted 마우스 이벤트 차이, 125% 확대에서 단일 전달, 재호출 차단, down/up 사이 본문 변경 차단, 가려진 버튼 및 상속 비활성 차단, 개인정보 없는 오류 진단을 확인했다. 6개 확인 통과. 첫 실행의 fixture 변수명 충돌 실패 기록도 보존했다. 기존 전체 검사/A/B/C 게시 시험을 반복하지 않았다.

실서비스 재시험 전 전체 게시물 조회: 4건, 동일 시험 제목 0건. 앱 자체 로그인 세션을 재사용했다. 현재 실제 앱에서 제목·본문·가상 PNG 1장 업로드 및 97 bytes 원본 해시 대조를 다시 통과하고 native 최종 확인창에 도달했다. 새 보내기 방식은 아직 실서비스에서 실행하지 않았으며 별도 최종 사용자 승인을 기다린다. 실제 재시험 결과는 승인 뒤 별도로 기록한다.

Actions 실행 요청 0회. 새 빌드·유료 자원·배포 없음. Windows 및 정식 운영 승인 상태는 이번 수정으로 바뀌지 않는다.
