# 전국판 배포 절차

설치 파일은 **GitHub Release 첨부 파일로만** 올린다. `downloads/nationwide` 브랜치에는 작은 글자 파일만 커밋한다. 옥구초판(Release Latest 방식)은 이 문서와 관계없다.

## 피드 두 개

| 파일 (`downloads/nationwide`) | 읽는 앱 | 내용 | 규칙 |
|---|---|---|---|
| `nationwide.yml` | 1.8.9~1.8.15 | 설치 파일 **이름** | **1.8.16에서 멈춤. 절대 바꾸지 않는다.** |
| `nationwide2.yml` | 1.8.16 이후 | Release 첨부 **전체 주소** | 버전마다 갱신 |

`nationwide2.yml`의 주소는 `https://github.com/rlasksk030/class/releases/download/nationwide-v<버전>/classroom-dashboard-nationwide-setup-<버전>-x64.exe`와 글자까지 같아야 한다(`app/update-feed-check.cjs`). 다르면 앱이 "설치 파일을 확인하지 못했습니다"를 띄우고 받지 않는다.

## 1.8.17부터 (매 버전)

1. **빌드:** `app/package.json` 버전을 올리고, `app/whats-new.js`의 `NOTES`에 새 버전의 "달라진 점"(제목 1줄, 항목 2~5줄)을 적는다. 업데이트 뒤 처음 켤 때 한 번 뜨는 안내다. 적지 않으면 아무것도 뜨지 않는다(`app/whats-new.test.cjs`가 형식을 검사). 그다음 `npm run dist:win`을 실행한다. 빌드 끝에 `scripts/make-nationwide-feeds.cjs`가 설치 파일의 크기·sha512를 대조하고 `dist/nationwide2.yml`을 Release 주소 형식으로 바꾼다. `dist/nationwide.yml`은 만들지 않는다.
2. **빌드 확인:** `dist/nationwide2.yml`의 version·url, 설치 파일 SHA-256, 설치 파일 안 `update-config.json`의 `channel`이 `nationwide2`인지 본다.
3. **태그:** `nationwide-v<버전>`을 push한다.
4. **Release:** `gh release create nationwide-v<버전> --repo rlasksk030/class --verify-tag --latest=false`로 만든다. 첨부는 설치 파일, blockmap, `nationwide2.yml`, `SHA256SUMS.txt`, `release-validation.json`이다.
5. **Release 확인:**
   - `gh release view`로 자산 5개가 모두 올라갔는지 본다.
   - 인증 없이 받은 설치 파일의 sha512가 피드 값과 같은지 본다: `curl -sSL <주소> | openssl dgst -sha512 -binary | base64` (redirect를 따라감).
   - `gh api repos/rlasksk030/class/releases/latest --jq .tag_name`이 옥구초 태그 그대로인지 본다.
6. **그다음에 피드:** `downloads/nationwide`에 `nationwide2.yml`, README(설치 링크는 Release 첨부 주소), `v<버전>-SHA256SUMS.txt`·`-release-notes.md`·`-release-validation.json`을 커밋하고(`[skip ci]`) push한다.
7. **피드 확인:** raw `nationwide2.yml`이 새 버전이고 raw `nationwide.yml`이 1.8.16 그대로인지 본다.

순서가 중요하다. 4~5를 마치기 전에 6을 하면 앱이 아직 없는 파일을 가리키는 피드를 받는다.

## 하지 않는 것

- `nationwide.yml` 수정, 설치 파일을 브랜치에 커밋(1.8.16 한 번뿐)
- 예전 설치 파일(1.8.8~1.8.16) 삭제, force push 같은 이력 다시 쓰기
- 전국판 Release를 Latest로 표시(옥구초판 앱이 `releases/latest`를 본다)

## 문제가 생기면

- **6 전:** Release를 지우거나 draft로 돌린다. 앱은 아직 이전 피드를 본다.
- **6 후:** `nationwide2.yml`을 직전 버전 내용으로 되돌려 커밋한다. 이미 업데이트한 앱은 되돌아가지 않는다(`allowDowngrade=false`).

## 1.8.16 (다리 버전, 한 번만)

- 위 1~5와 같다. 단, 빌드가 `dist/nationwide.yml`(파일 이름 형식)도 만든다.
- 6에서 설치 파일과 blockmap도 `downloads/nationwide`에 함께 커밋한다(마지막). `nationwide.yml`·`nationwide2.yml`·README·문서도 같은 커밋에 넣는다. 그래야 두 피드 모두 이미 있는 파일을 가리킨다.
- 설치 파일이 100MiB(104,857,600바이트) 이상이면 브랜치에 push할 수 없다. 그때는 멈추고 다른 방법을 정한다.
